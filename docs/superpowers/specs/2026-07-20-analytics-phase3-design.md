สถานะ: ร่าง — สำรวจข้อมูลแล้ว รอออกแบบรายละเอียดและอนุมัติ

3. **Lifetime Value สมาชิกและลูกค้า**
4. **ลูกค้าที่หายไปนาน** (เอาไว้ตามกลับ)

## ⚠️ ปัญหาที่ต้องแก้ก่อน — ชื่อโปรโมชั่นสะกดไม่เหมือนกัน

ช่อง `coupon_promo` เป็นข้อความพิมพ์มือ ทำให้โปรโมชั่นเดียวกันแตกเป็นหลายชื่อ

**ตัวอย่างจริง — "Happy Hours" ถูกพิมพ์ 8 แบบ:**

| ที่พิมพ์ | ครั้ง |
| -------- | ----- |
| `Happy Hours` | 38 |
| `Happy hours` | 13 |
| `Happy Hour` | 8 |
| `HappyHours` | 8 |
| `hApPy hOuRS` | 7 |
| (และอีก 3 แบบ) | 15 |
| **รวมจริง** | **89 ครั้ง · ส่วนลด ฿17,960** |

`Member` / `member` = 252 ครั้ง · `KOL` 2 แบบ · `ลด10%` 2 แบบ · `ลด15%` 2 แบบ

**ผลถ้าไม่แก้:** รายงานจะบอกว่า Happy Hours ถูกใช้ 38 ครั้ง ทั้งที่จริง 89 ครั้ง
โปรโมชั่นที่ได้ผลดีที่สุดจะดูเหมือนโปรฯ เล็กๆ และการตัดสินใจว่าจะทำโปรฯ ไหนต่อจะผิด

**ทำให้ตัวพิมพ์เล็กแล้วตัดช่องว่างยังไม่พอ** — `happyhour` กับ `happyhours` ยังแยกกันอยู่
(14 ครั้ง กับ 75 ครั้ง) ต้องมีการจับคู่ที่คนกำหนดเอง

### ทางเลือก

**ก) ตาราง `promotions` + `promotion_aliases`** — มีชื่อมาตรฐาน และตารางจับคู่ข้อความดิบ
เข้ากับชื่อมาตรฐาน seed จากการ normalize + จัดกลุ่มอัตโนมัติ แล้วให้เจ้าของร้านแก้ใน
หน้าตั้งค่า · แม่นที่สุด แต่ต้องมี UI จัดการ

**ข) normalize อย่างเดียว** (lower + ตัดช่องว่าง) · ง่ายสุด แต่ยังแยก `happyhour`/`happyhours`
และไม่ได้แก้ที่ต้นเหตุ

**ค) แก้ที่ต้นทาง** — เปลี่ยนช่องโปรโมชั่นในหน้า POS จากพิมพ์อิสระเป็น dropdown
เลือกจากรายการ · แก้ปัญหาถาวรสำหรับข้อมูลใหม่ แต่ข้อมูลเก่า 857 รายการยังต้องจับคู่อยู่ดี

**แนะนำ: ก + ค** — ทำ dropdown ในหน้า POS เพื่อไม่ให้เกิดปัญหาใหม่ และทำตารางจับคู่
เพื่อกู้ข้อมูลเก่า ทั้งสองอย่างใช้ตาราง `promotions` เดียวกัน

## สิ่งที่จะสร้าง (ร่าง)

### 1. Heatmap ชั่วโมง × วัน

view `v_hourly_density`: `weekday` (0-6) · `hour` (10-22) · `sessions` · `revenue`
หน้าแสดงเป็นตารางสี 7 แถว × 13 คอลัมน์ เข้มตามจำนวนงาน

**ต้องระวัง:** มีข้อมูลเวลาแค่ 70% ของรายการทั้งหมด ต้องบอกบนหน้าจอว่าคำนวณจากกี่รายการ
ไม่งั้นจะเข้าใจว่าเป็นภาพรวมทั้งหมด

### 2. ROI ส่วนลด

ต่อโปรโมชั่น (หลังจับคู่ชื่อแล้ว): จำนวนครั้ง · ส่วนลดที่ให้ไป · ยอดขายที่เกิด ·
ลูกค้าที่ใช้ · **ลูกค้าที่กลับมาซื้อซ้ำหลังใช้โปรฯ** (ตัวชี้วัดว่าโปรฯ สร้างลูกค้าประจำได้ไหม)

### 3. LTV ลูกค้า

ต่อลูกค้า: ยอดใช้จ่ายสะสม · จำนวนครั้ง · ค่าเฉลี่ยต่อครั้ง · ครั้งแรก/ครั้งล่าสุด ·
เป็นสมาชิกหรือไม่ เรียงตาม LTV

### 4. ลูกค้าที่หายไป

ลูกค้าที่เคยมาอย่างน้อย 2 ครั้ง แต่ไม่มาเกิน N วัน (ปรับได้) เรียงตาม LTV
เพื่อให้ตามกลับคนที่มีค่าที่สุดก่อน

## สิทธิ์

Heatmap และ ROI ส่วนลด → manager ขึ้นไป
LTV และลูกค้าหายไป → manager ขึ้นไป (มีข้อมูลติดต่อลูกค้า)
