# Boss Hub — หน้าเดียวจบสำหรับผู้บริหาร — Design

**วันที่:** 9 ส.ค. 2569
**สถานะ:** เจ้าของร้านอนุมัติ design แล้ว
**โปรเจกต์ที่ 2 จาก 4** (Speed Pass ✓ → **Boss Hub** → Intraday Pulse → Ask สุขกายา)

## เป้าหมาย

ผู้บริหารเปิดหน้าเดียวแล้วได้**คำตอบ**ของ 4 คำถามหลักทันที โดยไม่ต้องเปิดหลายหน้า:
วันนี้/เดือนนี้เป็นไงเทียบปกติ · เงินไปไหนกำไรเหลือเท่าไหร่ · ลูกค้าคนไหนต้องดูแลด่วน ·
ทีมเป็นไง — ทุกการ์ดขึ้นต้นด้วย**ประโยคคำตอบภาษาคน** แล้วค่อยตามด้วยตัวเลข
และกดทะลุไปหน้าเจาะลึกเดิมได้ทุกจุด

## หลักคิด

- **ประกอบจากของที่มี ไม่สร้างวิเคราะห์ใหม่จากศูนย์** — ระบบมีวิเคราะห์กระจายอยู่ 7 หน้าแล้ว
  (overview, reports, insights×3, finance, commission) Boss Hub คัด "คำตอบ" มารวม
  แล้วชี้เป้ากลับไปหน้าเดิมเป็น drill-down
- **Answer-first**: หัวการ์ดเป็นประโยคภาษาไทยที่ตัดสินให้เลย เช่น
  "เดือนนี้วิ่งเร็วกว่าเดือนก่อน 12% ณ วันเดียวกัน" — ไม่ใช่แค่ตาราง
- **หน้าเดิม 7 หน้าไม่ถูกรื้อ** — ยังอยู่ครบทำหน้าที่เจาะลึก

## ตำแหน่ง: แทนที่ `/overview`

- Boss Hub คือ `/overview` โฉมใหม่ — ไม่เพิ่มหน้าที่ 8 เข้าเมนูผู้บริหาร
- ชื่อเมนูเดิม "ภาพรวม" คงไว้ (ผู้ใช้คุ้นแล้ว) · สิทธิ์เดิม: manager ขึ้นไป (`canSeeInsights`)
- เนื้อหาเดิมของ overview ที่มีค่า ถูกจัดเข้าโซนใหม่ (ดูตารางท้ายสเปก) — ไม่มีของหาย

## โครงหน้า — 4 โซน

### โซน 1: "วันนี้/เดือนนี้ ดีกว่าหรือแย่กว่าปกติ?" (แถบบนสุด เต็มความกว้าง)

- **ประโยคคำตัดสิน 1-2 ประโยค** สรุปทั้งวันนี้และเดือนนี้ เช่น
  "เดือนนี้วิ่งเร็วกว่าเดือนก่อน 12% ณ วันเดียวกัน · วันนี้ทำได้ 8,450฿ สูงกว่าค่าเฉลี่ยวันเสาร์ (+9%)"
- **กติกาเทียบที่เป็นธรรม** (หัวใจของโซนนี้):
  - เดือนนี้ vs เดือนก่อน **ตัดที่วันเดียวกัน** (MTD vs MTD) — ห้ามเอาเดือนเต็มเทียบเดือนครึ่ง
  - วันนี้ vs **ค่าเฉลี่ยวันในสัปดาห์เดียวกัน 4 สัปดาห์ล่าสุด** (เสาร์เทียบเสาร์)
    — ถ้าข้อมูลย้อนหลังไม่ครบ 4 สัปดาห์ ใช้เท่าที่มีและบอกจำนวนสัปดาห์ที่ใช้
  - วันนี้ยังไม่จบวัน — ป้ายกำกับ "ณ ตอนนี้" ให้ชัดว่าตัวเลขยังวิ่งอยู่
- เป้าเดือน + แถบ progress + run-rate ที่ต้องทำต่อวัน (ยกจาก overview เดิม)
- ตัวเลขประกอบ: ยอดขายวันนี้/จำนวนบิลวันนี้ · ยอด MTD vs เดือนก่อน MTD (delta ฿ และ %)

### โซน 2: "เงินไปไหน กำไรจริงเหลือเท่าไหร่?"

- หัวการ์ด: ประโยคสรุป เช่น "เดือนนี้กำไรแล้ว 132,000฿ (margin 34%) — ดีกว่าเดือนก่อน ณ วันเดียวกัน"
- กำไรสุทธิ MTD (รายรับ − ค่ามือหมอ − รายจ่ายอื่น ตามสูตร accrual ของ `/finance`) + margin
  + delta vs เดือนก่อน MTD
- **ชิปรายจ่ายผิดปกติ** สูงสุด 3 ชิป — reuse ตัวตรวจ anomaly ของ `insights/expenses`
  (เทียบ median 3 เดือน) เอาเฉพาะระดับ alert/warn เรียงตามความแรง แต่ละชิปกดไป
  `/insights/expenses` — ถ้าไม่มีผิดปกติ แสดง "รายจ่ายปกติดี ✓"
- กราฟรายรับ-รายจ่าย 6 เดือน + เส้นกำไร (ยกจาก overview เดิม ใช้ component เดิม ย่อขนาด)
- ลิงก์เจาะลึก: `/finance` (P&L เต็ม), `/insights/expenses`

### โซน 3: "ลูกค้าคนไหนต้องดูแลด่วน?" (ลิสต์ลงมือทำได้)

- ลิสต์เดียวรวม 3 แหล่ง เรียงตามลำดับความสำคัญ สูงสุด ~10 แถว:
  1. **วันเกิดวันนี้/พรุ่งนี้** (ยังไม่อวยพร — กติกาเดียวกับกระดิ่ง/`/crm`) — บนสุดเพราะมีวันหมดอายุ
  2. **ลูกค้าประจำหายไปนาน** — กติกาเดียวกับแท็บ "หายไปนาน" ใน CRM (≥2 ครั้ง, ไม่มาเกิน 60 วัน)
     เรียงตาม LTV เอา top 5 — คนมูลค่าสูงที่กำลังหลุดมือ
  3. **สมาชิกเครดิตใกล้หมด** (bucket ต่ำสุดจาก logic เครดิตของ overview เดิม) top 3 —
     โอกาสชวนเติมเงิน
- แต่ละแถว: ชื่อ · เหตุผลที่โผล่ (ป้ายสี: 🎂 วันเกิด / 💤 หาย 74 วัน / 💳 เครดิตเหลือ 120฿) ·
  มูลค่า (LTV หรือเครดิตคงเหลือ) · **กดแล้วไป `/crm` โฟกัสลูกค้าคนนั้น** (หน้า CRM มีปุ่ม
  โทร/ส่ง LINE/บันทึกผลครบอยู่แล้ว — Boss Hub ชี้เป้า ไม่ทำซ้ำ)
- ว่างทั้งลิสต์ → "ไม่มีเคสด่วนวันนี้ ✓"

### โซน 4: "ทีมเป็นไง ใครทำรายได้ดีสุด?"

- หัวการ์ด: ประโยคสรุป เช่น "เดือนนี้ครูแอนทำรายได้สูงสุด 41,200฿ · วันนี้เข้างาน 5 คน คิวแน่นช่วงเย็น"
- **ท็อป 5 หมอนวดเดือนนี้**: จำนวนคิว + รายได้ที่ทำให้ร้าน (จาก sales ของเดือน) —
  แถบเทียบสัดส่วนแบบ bar ในแถว
- **ป้ายการันตี**: หมอที่เดือนนี้กินการันตีเกินครึ่งของวันทำงาน — สัญญาณคิวน้อยผิดปกติ
  (ใช้ข้อมูลเดียวกับหน้า `/commission`)
- **สถานะวันนี้**: กี่คนเช็คอินเข้างาน (จาก checkin) · จำนวนคิววันนี้ทั้งหมด/เสร็จแล้ว (จาก queue)
- ลิงก์เจาะลึก: `/commission/summary`, `/team`, `/checkin`

### Layout

- **มือถือ**: โซน 1 → 2 → 3 → 4 เรียงลงมา การ์ดเต็มความกว้าง
- **จอกว้าง (≥lg)**: โซน 1 เต็มแถวบน · ล่างเป็นกริด — โซน 2 กว้าง 2 ส่วน, โซน 3+4 ซ้อนกันคอลัมน์ขวา 1 ส่วน
  (ลิสต์ลูกค้า/ทีมแคบได้ กราฟการเงินต้องการที่กว้าง)

## ของเดิมใน overview ไปไหน

| ของเดิม | ที่ใหม่ |
|---|---|
| hero รายรับ/เป้า/run-rate/margin | โซน 1 (เป้า+run-rate) + โซน 2 (กำไร/margin) |
| กราฟ 6 เดือน + margin line | โซน 2 (กราฟรวม 1 ตัว — margin line ยุบเข้ากราฟหลัก) |
| เครดิตใกล้หมด + liability | โซน 3 (top 3 เข้าลิสต์) — ตาราง bottom-10 เต็มย้ายไปลิงก์ `/members` |
| แถว YTD / member activity | ตัดจากหน้าแรก — มีใน `/finance` และ `/reports` อยู่แล้ว (ลดความแน่น) |
| ตาราง 6 เดือน | ตัด — ซ้ำกับกราฟ + มีเต็มใน `/finance` |

## สถาปัตยกรรม

### หน่วยใหม่ (แต่ละตัวมีหน้าที่เดียว ทดสอบแยกได้)

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/period-compare.ts` + test | **กติกาเทียบช่วงกลางของระบบ**: `mtdRange(month)`, `mtdCompare(...)`, `sameWeekdayAverage(...)`, `verdictSentence(...)` — pure functions ทุกโซนใช้กติกาเดียวกัน |
| `src/lib/boss-hub.ts` + test | รวม/จัดอันดับข้อมูลเป็น view-model ของ 4 โซน: `buildCareList(...)` (รวม 3 แหล่ง เรียงความสำคัญ), `topTherapists(...)`, `guaranteeFlags(...)` — pure functions รับข้อมูลดิบ คืนโครงพร้อม render |
| `src/app/(app)/overview/page.tsx` (เขียนใหม่) | ยิง query ขนานทั้งชุด → ส่งเข้า lib → render 4 โซน |
| `src/app/(app)/overview/` components ย่อยต่อโซน | `verdict-strip.tsx`, `money-zone.tsx`, `care-list.tsx`, `team-zone.tsx` — แยกไฟล์ต่อโซน ไม่ให้ page โต |
| `src/app/(app)/overview/loading.tsx` (ปรับ) | skeleton ให้ตรงโครง 4 โซนใหม่ |

### ของที่ reuse (ห้ามเขียนซ้ำ)

- anomaly รายจ่าย: logic ใน `src/lib/expense-analytics.ts` (ตัวเดียวกับ insights/expenses)
- ลูกค้าหายไปนาน: กติกา dormant ใน `src/lib/crm.ts` / query แบบเดียวกับ `crm/customer-insights.tsx`
- วันเกิด: `birthdayTodayCustomers()` (+ ขยายรับ "พรุ่งนี้")
- เครดิต bucket: logic เดิมจาก overview (ย้ายเข้า `boss-hub.ts` พร้อม test ถ้ายังไม่มี)
- กราฟ: `src/components/charts/*` + `src/lib/chart.ts` เดิม (SVG ล้วน ไม่เพิ่ม dependency)
- cache: `getShopSettingsCached()`/`getTherapistsCached()` จาก Speed Pass

### Data flow

query ทั้งหมดวิ่งขนานใน `Promise.all` เดียว (บทเรียน Speed Pass) → pure functions ใน lib
แปลงเป็น view-model → components render — ไม่มี client fetch, ไม่มี realtime (ค่าสดพอด้วยการโหลดหน้า
และ Intraday Pulse โปรเจกต์ถัดไปจะดูแลการเด้งระหว่างวัน)

### Error handling

- โซนไหน query ล้ม → โซนนั้นแสดงการ์ด "โหลดไม่สำเร็จ ลองรีเฟรช" โซนอื่นแสดงปกติ
  (ไม่ให้คำถามเดียวพังทั้งหน้า) — error ระดับหน้าใหญ่มี `(app)/error.tsx` จาก Speed Pass รับอยู่แล้ว
- เดือนแรกที่ข้อมูลไม่พอเทียบ (ไม่มีเดือนก่อน/ไม่มี 4 สัปดาห์) → ประโยคคำตัดสินบอกตรงๆ
  ว่าเทียบกับอะไรได้บ้าง ไม่เงียบและไม่โชว์ delta หลอก

### การทดสอบ

- `period-compare.ts`: test ครอบ MTD ข้ามปี (ม.ค. vs ธ.ค.), เดือนสั้น/ยาว (31 มี.ค. เทียบ ก.พ.),
  วันแรกของเดือน, ข้อมูลไม่ครบ 4 สัปดาห์
- `boss-hub.ts`: test การเรียงลิสต์ดูแลด่วน (วันเกิดชนะ dormant ชนะเครดิต), tie-break ตาม LTV,
  ลิสต์ว่าง, guarantee flag ขอบเขตครึ่งพอดี
- test เดิมทั้งหมดผ่าน + lint + build
