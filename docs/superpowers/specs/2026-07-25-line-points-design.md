# ระบบสะสมแต้ม SOOKKAYA Points (ผ่านไลน์)

**เป้าหมาย:** ลูกค้าสะสมแต้มจากการใช้จ่ายจริง ดู/แลกแต้มในไลน์ได้เอง → จูงใจกลับมาซ้ำ + พาลูกค้ามาผูกไลน์ (ฐานสำหรับ CRM/broadcast ต่อไป)

## นโยบาย (ตัดสินใจแล้ว)

- **ได้แต้ม:** ทุก 100฿ ที่จ่ายจริง = 1 แต้ม (ปัดลง) จากยอดสุทธิของบิลที่ผูกชื่อลูกค้า + ยอดเติมเงินสมาชิก (เงินสดรับจริง) · **จ่ายด้วยเครดิตสมาชิกไม่ได้แต้ม** (ได้ไปแล้วตอนเติม) · เริ่มนับจากวันเปิดระบบ ไม่มีแต้มย้อนหลัง
- **อายุแต้ม:** แต้มที่ได้ปีนี้ใช้ได้ถึงสิ้นปีถัดไป (เก็บ expires_at ต่อรายการ · การตัดแต้มหมดอายุจริงรอบแรกคือสิ้นปี 2027 — v1 แสดงข้อมูล ยังไม่บังคับตัด บันทึกเป็นงานตามก่อนถึงกำหนด)
- **การแลก:** ลูกค้ากดแลกในไลน์ → แต้มถูกกันออกทันที → ได้คูปองรหัส 6 หลัก อายุ 30 วัน → โชว์พนักงาน → พนักงานกรอกรหัสใน POS → บันทึกเป็นบิลส่วนลดเต็มราคา (เก็บ 0 บาท, โปรฯ = "แลกแต้ม") → **ค่ามือหมอจ่ายปกติ** · คูปองหมดอายุ = คืนแต้มอัตโนมัติ

## การผูกตัวตน

ใช้กลไกระบบจองเดิมทั้งหมด: LIFF เดียวกัน (endpoint /book) → หน้าแต้มอยู่ที่ **`/book/points`** เปิดตรงจากลิงก์ `https://liff.line.me/<LIFF_ID>/points` (ใส่ Rich Menu ได้) · ครั้งแรกยืนยันเบอร์ → จับคู่ customers ด้วยเบอร์ (ผ่าน line_accounts เดิม) · ชื่อไลน์อัปเดตทุกครั้งที่เปิด แยกจากชื่อในระบบร้าน · ฝั่งร้าน: โปรไฟล์ลูกค้าโชว์ชื่อไลน์+รูป และแอดมินย้ายลิงก์ไลน์ไปลูกค้าที่ถูกได้ (เคสเบอร์เก่า/ลูกค้าซ้ำ — การรวมร่างลูกค้าเต็มรูปเป็นงานถัดไป)

## ข้อมูล (RLS lock ทุกตาราง แบบ line_accounts · ฝั่งลูกค้าอ่าน-เขียนผ่าน server action ตรวจ idToken + service client เท่านั้น)

1. `point_rewards` — ของรางวัล: name, service_id (nullable), points_cost, is_active, sort · staff (authenticated) จัดการผ่านหน้าตั้งค่า
2. `point_transactions` — สมุดบัญชีแต้ม: customer_id, delta (+/-), reason, sale_id / topup_id / redemption_id (ที่มา), expires_at (เฉพาะรายการบวก = 31 ธ.ค. ปีถัดไป), created_by
3. `point_redemptions` — คูปอง: customer_id, reward_id+ชื่อ+แต้มที่ใช้ (snapshot), code unique 6 ตัว (ตัดตัวสับสน 0/O/1/I), status issued→used/cancelled/expired, expires_at (+30 วัน), used_sale_id, used_by
4. view `v_point_balances` (security_invoker): แต้มคงเหลือ = sum(delta) ต่อลูกค้า

## จุดเกิดแต้ม (server)

- `createSale` สำเร็จ + มี customer_id + net > 0 + ไม่ใช่เครดิตสมาชิก → insert แต้ม (ผูก sale_id)
- `updateSale` → คำนวณ delta ใหม่ทับรายการเดิมของ sale นั้น · `deleteSale` → ลบรายการแต้มของ sale นั้น (กัน drift)
- เติมเงินสมาชิก → แต้มจาก cash_received (ผูก topup_id) · ลบใบเติม → ลบแต้ม

## ฝั่งลูกค้า `/book/points` (ใน LIFF)

แต้มคงเหลือตัวใหญ่ + บรรทัด "หมดอายุ 31 ธ.ค. XXXX" · คูปองที่ยังไม่ใช้ (รหัส+วันหมดอายุ) · แคตตาล็อกรางวัล → กดแลก (ยืนยันก่อน) → แต้มพอ: กันแต้ม + สร้างคูปอง → โชว์ทันที · ประวัติแต้ม 20 รายการล่าสุด · เปิดหน้า = auto-expire คูปองเกินกำหนด + คืนแต้ม · ลิงก์ "แต้มของฉัน" ในหน้า /book หลักด้วย

## ฝั่งร้าน

1. **POS:** ช่อง "คูปองแลกแต้ม" + ปุ่มตรวจ → เจอคูปอง issued ไม่หมดอายุ → เติมลูกค้า/เมนู (จากรางวัล)/ส่วนลดเต็ม/โปรฯ "แลกแต้ม" ให้อัตโนมัติ → บันทึกบิลสำเร็จ → คูปอง used + ผูก sale
2. **ตั้งค่า → แท็บของรางวัล:** เพิ่ม/แก้/ปิดรางวัล (ชื่อ · แต้ม · ผูกเมนู)
3. **โปรไฟล์ลูกค้า:** แต้มคงเหลือ + ประวัติ + ชื่อไลน์/รูป + ปุ่มปรับแต้มมือ (delta + เหตุผลบังคับ) + ปุ่มย้ายลิงก์ไลน์มาลูกค้าคนนี้

## ตรวจทาน

reconciliation เพิ่ม 2 ข้อ: (23) ไม่มีลูกค้าแต้มติดลบ = 0 · (24) คูปอง used ที่ไม่มีบิลผูก = 0 · unit tests: สูตรแต้ม/วันหมดอายุ/รหัสคูปอง (TDD) · E2E มือ: ลูกค้าจริงแลกผ่านไลน์ → POS กรอกรหัส → บิล 0 บาท → ค่ามือหมอครบ

## ไม่ทำรอบแรก

Tier สมาชิก · push แจ้งเตือนอัตโนมัติ · โอนแต้ม · รวมร่างลูกค้าซ้ำเต็มรูป · บังคับตัดแต้มหมดอายุ (ก่อนสิ้นปี 2027)
