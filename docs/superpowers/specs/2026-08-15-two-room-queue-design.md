# การ์ดคิวถือได้สองห้อง — เมนูที่ย้ายห้องกลางคัน

**วันที่:** 2026-08-15
**สถานะ:** อนุมัติแล้ว รอเขียนแผน

## ที่มา

พนักงานหน้าร้านแจ้งว่ากดเลือกห้องให้คิวถัดไปไม่ได้ เพราะห้องยังถูกล็อกโดยคิวก่อนหน้า
ทั้งที่ลูกค้านวดเสร็จและย้ายไปนวดต่อที่ห้องไทยแล้ว

สอบถามแล้วพบว่านี่**ไม่ใช่เคสยกเว้น แต่เป็นวิธีทำงานปกติของเมนู "นวดคลายเท้า & คอบ่าไหล่"**

| เมนู | ครึ่งแรก | ครึ่งหลัง | ใช้กี่ห้อง |
|---|---|---|---|
| 60 นาที | โซฟานวดเท้า 30 | คอบ่าไหล่**บนโซฟาเดิม** 30 | 1 ห้อง |
| 90 นาที | โซฟานวดเท้า 45 | คอบ่าไหล่**เตียงไทย** 45 | **2 ห้อง** |
| 120 นาที | โซฟานวดเท้า 60 | คอบ่าไหล่**เตียงไทย** 60 | **2 ห้อง** |

ลูกค้ารีเควสอยู่โซฟายาว ๆ ไม่ย้ายห้องได้ ดังนั้นการย้ายห้องเป็นค่าตั้งต้น ไม่ใช่กฎตายตัว

นอกจากนี้ยังมีเคสลูกค้าซื้อสองโปรแกรมแยกบิล (เช่น นวดเท้า 60 แล้วต่อคอบ่าไหล่ 60 ในห้องสปา)
ซึ่งได้การ์ดคนละใบอยู่แล้ว **ไม่อยู่ในขอบเขตของสเปกนี้**

## สภาพปัจจุบัน

`queue_entries` เก็บ `bed_id` ได้ห้องเดียวต่อการ์ด และระบบถือว่าห้องนั้นถูกครองตั้งแต่เวลาเริ่ม
(`started_at` ถ้ากดเริ่มนวดแล้ว ไม่งั้นใช้ `start_time`) ยาวจนครบ `duration_min`
ป้าย "เสร็จสิ้น" บนการ์ดเป็นค่าที่คำนวณจากนาฬิกาเท่านั้น **ไม่ได้ปล่อยห้อง**
(`src/lib/queue-status.ts` — คอมเมนต์ระบุชัดว่าไม่แตะ status ในฐานข้อมูล)

ผลคือระบบเข้าใจผิดสองทางพร้อมกัน: คิดว่าเก้าอี้ยังไม่ว่างทั้งที่ลูกค้าย้ายไปแล้ว
และคิดว่าเตียงไทยว่างทั้งที่มีคนอยู่

**ตัวเลขยืนยัน:** คิวเมนูนี้ 40 ใบในระบบ — ลงเก้าอี้ 33 ใบ **ลงเตียงศูนย์ใบ**
ห้องที่สองไม่เคยถูกบันทึกเลยสักครั้งตั้งแต่เปิดใช้ระบบ

**และเรื่องนี้อธิบายข้อตรวจที่ค้างอยู่:** `bed_double_booked` ใน `supabase/reconciliation.sql`
FAIL มาตั้งแต่ 9 ส.ค. 2026 จากคู่นี้ — ทั้งคู่เป็นเมนูเดียวกันนี้

> เอ็ม เมธี · 13:55 · 120 นาที · เก้าอี้ 3 → ตามกติกาคือโซฟา 13:55–14:55 แล้วย้ายเตียงไทย
> กอล์ฟฟี่ · 15:00 · 90 นาที · เก้าอี้ 3

ถ้าเอ็ม เมธี ย้ายออกตอน 14:55 จริง กอล์ฟฟี่เริ่ม 15:00 **ไม่ได้ชนอะไรเลย** พนักงานทำถูกมาตลอด
ระบบต่างหากที่บันทึกความจริงไม่ครบ **ห้ามไปแก้ข้อมูลคิวคู่นั้น** เพราะไม่มีอะไรผิด

**แก้ไขภายหลัง (ตัดสินใจกลางทางระหว่างทำ):** ข้อตรวจนี้**ไม่ได้หายไปเป็น 0** อย่างที่ร่างสเปกนี้
เขียนไว้ทีแรก — คู่ 9 ส.ค. เกิดขึ้น**ก่อน**คอลัมน์ `bed_id_2` จะมีอยู่จริง จึงไม่มีทางย้อนไปบันทึก
ห้องที่สองของการ์ดใบนั้นได้เลย (backfill เท่ากับกุเตียงไทยใบใดใบหนึ่งขึ้นมาเองโดยไม่มีใครยืนยันได้)
ทางที่เลือกคือ**เก็บเป็น known exception ค่า 1 ถาวร** ใน `supabase/reconciliation.sql`
(ดู Task 6) — ไม่ backfill ไม่แก้ข้อมูล เพียงบันทึกไว้ว่าทำไมค่านี้ไม่ใช่ 0
**ถ้าเลขขึ้นมากกว่า 1 = มีคู่ใหม่ที่ต้องสืบทันที** การ์ดที่สร้างหลังฟีเจอร์นี้ขึ้นระบุ `bed_id_2`
ได้แล้ว จึงไม่ควรมีข้อยกเว้นใหม่งอกขึ้นมาอีก

## ขอบเขต

**ทำ**

1. `queue_entries` เก็บห้องที่สองได้
2. `services` รู้ว่าเมนูไหนย้ายห้องกลางคัน
3. สูตรกลางที่ตอบว่า "การ์ดใบนี้ยึดห้องไหน ช่วงไหน" แล้วให้ทุกทางเข้าใช้ร่วมกัน
4. หน้าจอสร้าง/แก้คิว และกล่องย้ายเตียง เลือกห้องที่สองได้

**ไม่ทำ**

- ไม่แตะข้อมูลเก่า 40 ใบที่บันทึกห้องเดียว — เป็นประวัติ
- ไม่แก้ข้อมูลคิวคู่ที่ `bed_double_booked` ฟ้อง (เหตุผลข้างบน)
- ไม่เพิ่มห้องที่สองในตาราง `sales` — บิลไม่ต้องรู้เรื่องห้อง กระดานคิวเป็นเจ้าของข้อมูลนี้
- ไม่รองรับเกิน 2 ห้อง และไม่รองรับจุดแบ่งที่ไม่ใช่ครึ่ง — ร้านไม่มีเคสนั้น (Boss ยืนยัน 15 ส.ค. 2026)
- ไม่ทำเคสซื้อสองโปรแกรมแยกบิล — ได้การ์ดคนละใบอยู่แล้ว

## Global Constraints

- **จุดแบ่งคือครึ่งหนึ่งของ `duration_min` เสมอ** ไม่เก็บเป็นข้อมูล คำนวณเอาทุกครั้ง
- ห้องที่สองว่างได้เสมอ — ว่าง = อยู่ห้องเดียวตลอด = **พฤติกรรมเดิมทุกประการ**
- ทุกจุดที่ถามว่า "ห้องนี้ว่างไหม" ต้องผ่านสูตรกลางตัวเดียว ห้ามเขียนช่วงเวลาเอง
- เวลาที่ใช้ตัดสินการครองห้องคือ `bedStartMin()` เดิม (เริ่มจริงถ้ามี ไม่งั้นเวลาจอง) — ห้ามเปลี่ยน
- คอมเมนต์และข้อความบนหน้าจอเป็นภาษาไทย · ชื่อตัวแปรเป็นภาษาอังกฤษเสมอ
- migration ใช้ MCP `apply_migration` (project `jrioyrmicioqammeevgh`) แล้วเก็บสำเนาลง
  `supabase/migrations/` ห้ามรัน `supabase db push`
- ทุกครั้งที่ generate `src/types/database.ts` ต้องใส่คอมเมนต์หัวไฟล์สี่บรรทัดกลับเข้าไป
  ก่อน `export type Json =`
- ขึ้น production: push เข้า main แล้วสั่ง `vercel deploy --prod` เอง — push ไม่ deploy อัตโนมัติ
  และต้องเช็ค alias หลัง deploy ทุกครั้งว่าชี้ build ใหม่จริง

## ส่วนที่ 2 — สูตรกลาง `bedSegments()`

อยู่ใน `src/lib/queue.ts` ที่เดียวกับ `bedStartMin` / `busyBedIds`

```
bedSegments(entry) → { bedId, startMin, durationMin }[]

มี bed_id_2:  [{bed_id,   start,        half},
               {bed_id_2, start + half, duration − half}]
ไม่มี:        [{bed_id,   start,        duration}]
ไม่มี bed_id เลย: []
```

โดย `start = bedStartMin(entry)` และ `half = Math.floor(duration_min / 2)`

`Math.floor` เพื่อให้ครึ่งหลังได้เศษไปเมื่อนาทีเป็นเลขคี่ — เมนูจริงทั้งหมดหารลงตัว
แต่ต้องไม่พังถ้าวันหนึ่งมีเมนูนาทีคี่

**ทุกทางเข้าที่เช็คห้องว่างต้องเปลี่ยนมาใช้ตัวนี้** ปัจจุบันมี:

| ไฟล์ | ใช้อะไรอยู่ | หน้าที่ |
|---|---|---|
| `src/lib/queue.ts` — `busyBedIds` | ช่วงเดียว | ฝั่งจอ: ปิดปุ่มห้องที่ไม่ว่าง |
| `src/lib/bed-clash.ts` — `firstClash` | ช่วงเดียว | ฝั่ง server: กันจองซ้อน |
| `queue/queue-actions.ts:91` | `firstClash` | สร้าง/แก้/ย้ายคิว |
| `sale-actions.ts:62` | `firstClash` | เตือนตอนกดเก็บเงิน |
| `queue/queue-form-dialog.tsx` 3 จุด | `busyBedIds` | ช่องเลือกห้องในกล่องคิว |
| `queue/queue-card.tsx:753` | `busyBedIds` | กล่องย้ายเตียง |
| `pos/pos-form.tsx:673` | `busyBedIds` | ช่องเลือกห้องตอนเก็บเงิน |

ทั้งสองฟังก์ชันต้องเทียบ **ช่วงของผู้ถาม × ช่วงของแต่ละการ์ด** ไม่ใช่ช่วงเดียวต่อการ์ดอีกต่อไป
และตัวผู้ถามเองก็อาจมีสองช่วง (ตอนเลือกห้องให้การ์ดที่ย้ายห้อง)

`CLASH_COLUMNS` ต้องเพิ่ม `bed_id_2` เพื่อให้ทุกทางเข้าดึงข้อมูลครบ

## ส่วนที่ 3 — หน้าจอ

**กล่องสร้าง/แก้คิว (`queue-form-dialog.tsx`)**
เมื่อเมนูที่เลือกมี `splits_room` ให้ขึ้นช่องเลือกห้องที่สอง พร้อมป้ายบอกช่วงเวลาจริงที่คำนวณจาก
เวลาเริ่มกับนาทีของเมนู เช่น *"เตียงช่วงครึ่งหลัง · 15:00–16:00 น."* — ไม่ใช่ป้ายลอย ๆ ว่า "ห้องที่ 2"
ช่องนี้เว้นว่างได้เสมอ พร้อมข้อความกำกับว่าเว้นว่าง = ลูกค้าอยู่ห้องเดียวตลอด

ช่องแรกเช็คห้องว่างของ**ครึ่งแรก** ช่องที่สองเช็คของ**ครึ่งหลัง** — คนละช่วงเวลา

**กล่อง "🔁 ย้ายเตียง/เปลี่ยนหมอ" (`queue-card.tsx`)**
เพิ่มช่องห้องที่สองแบบเดียวกัน ให้แก้ทีหลังได้ตามที่ Boss เลือก
กล่องนี้เช็คห้องว่างเฉพาะ "ช่วงที่เหลือ" อยู่แล้ว (`checkStart = max(start, now)`) — ตรรกะนั้นคงไว้
แต่ต้องคิดแยกรายช่วงเมื่อการ์ดมีสองห้อง

**กระดานคิว** — ป้ายบนการ์ดควรบอกให้เห็นว่าใช้สองห้อง เช่น `เก้าอี้ 3 → ห้องไทย เตียง 2`
เพื่อให้พนักงานเห็นจากกระดานได้เลยโดยไม่ต้องเปิดการ์ด

## ส่วนที่ 4 — server actions

`createQueueEntry` · `updateQueueEntry` · `moveQueueEntry` รับและบันทึก `bed_id_2`

ฟอร์มแก้บิลไม่มีช่องห้องที่สอง ถ้าเผลอเขียน null ทับจะลบห้องที่พนักงานเลือกไว้ทิ้ง

## ส่วนที่ 5 — การทดสอบ

**`bedSegments()` (เทสต์หน่วย ครอบให้ครบ)**
- ไม่มีห้องที่สอง → 1 ช่วง ยาวเต็ม `duration_min` (พิสูจน์ว่าพฤติกรรมเดิมไม่เปลี่ยน)
- มีห้องที่สอง 120 นาที → 2 ช่วง ช่วงละ 60 ต่อกันพอดี ไม่มีรู ไม่ทับกัน
- นาทีคี่ (เช่น 45) → ครึ่งหลังได้เศษ รวมสองช่วงต้องเท่ากับ `duration_min` เป๊ะ
- ไม่มี `bed_id` เลย → คืนอาร์เรย์ว่าง
- กดเริ่มนวดแล้ว (`started_at`) → ทั้งสองช่วงเลื่อนตามเวลาเริ่มจริง

**การชน (เทสต์หน่วยของ `firstClash` / `busyBedIds`)**
- **เคสจริง 9 ส.ค.:** การ์ด A เก้าอี้ 3 เวลา 13:55 120 นาที มีห้องที่สอง → การ์ด B เก้าอี้ 3
  เวลา 15:00 **ต้องไม่ชน** · แต่ถ้า A ไม่มีห้องที่สอง **ต้องชน** (พฤติกรรมเดิม)
- ครึ่งหลังของ A ชนกับครึ่งแรกของ B บนเตียงเดียวกัน → ต้องจับได้
- ชนขอบพอดี (A จบ 15:00 B เริ่ม 15:00) → ไม่นับชน เหมือนกติกาเดิม

**เทสต์เดิมทั้งหมดของ `queue`/`bed-clash` ต้องผ่านโดยไม่แก้แม้แต่ตัวอักษรเดียว**
ถ้าต้องแก้เทสต์เดิมแปลว่าเปลี่ยนพฤติกรรมของการ์ดห้องเดียวไปด้วย ซึ่งผิดเจตนา

**`reconciliation.sql`** — ข้อ `bed_double_booked` ต้องอัปเดตให้เข้าใจสองห้อง
มิฉะนั้นมันจะยังฟ้องเคส 9 ส.ค. ต่อไป และจะฟ้องผิดกับทุกคิวที่ย้ายห้องนับจากนี้
