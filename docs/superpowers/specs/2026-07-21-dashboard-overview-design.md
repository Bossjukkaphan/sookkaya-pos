| รอบ | เนื้อหา | สถานะ |
| --- | ------- | ----- |
| **1** | **ระบบหน้าตา (เมนู · การ์ด · กราฟ) + หน้า `/overview`** | **spec นี้** |

**เหตุผลที่ทำ cockpit ก่อน:** หน้านี้ใช้ของใหม่ครบทุกชิ้น (เมนู การ์ด KPI กราฟ แถบเป้า)
ถ้าระบบหน้าตาออกแบบผิด จะรู้ตั้งแต่รอบแรก ไม่ใช่ตอนรื้อไปแล้ว 7 หน้า

**เหตุผลที่ทำหน้าพนักงานท้ายสุด:** `/pos` และ `/today` คือหน้าที่ใช้ทำมาหากินวันละหลายสิบครั้ง
เปลี่ยนแล้วพนักงานต้องเรียนรู้ใหม่ ควรเปลี่ยนตอนที่รู้แล้วว่าระบบใหม่ใช้ได้จริง

## สถาปัตยกรรม

### แก้ view `v_monthly_pl` — เพิ่ม 3 คอลัมน์

ใช้ window function คำนวณในตัว view เอง หน้าเว็บอ่านแถวเดียวได้ครบทั้ง MTD · YTD · เดือนก่อน

| คอลัมน์ใหม่ | ความหมาย |
| ----------- | -------- |
| `prev_net_revenue` | รายได้ของเดือนก่อนหน้า (ใช้คำนวณลูกศรขึ้น/ลง) |
| `ytd_net_revenue` | รายได้สะสมตั้งแต่ต้นปีถึงเดือนนี้ |
| `ytd_profit_cash` | กำไรเงินสดสะสมตั้งแต่ต้นปีถึงเดือนนี้ |

สะสม "ต้นปี" หมายถึง partition ตาม `left(month, 4)` ไม่ใช่ 12 เดือนย้อนหลัง
คอลัมน์เดิมทั้ง 13 ตัวไม่เปลี่ยน หน้า `/finance` ที่ใช้อยู่จึงไม่กระทบ

### แหล่งข้อมูลของแต่ละบล็อก

| บล็อก | แหล่ง |
| ----- | ----- |
| Hero: รายได้ · กำไรเงินสด · margin · cash in · เทียบเดือนก่อน | `v_monthly_pl` แถวของเดือนที่เลือก |
| แถบเป้าเดือนนี้ | `settings.monthly_target` (ปัจจุบัน 400,000) |
| KPI: รายได้ YTD · กำไร YTD · เซสชันเดือนนี้ · จำนวนสมาชิก | `v_monthly_pl` + `count(customers where customer_type = 'สมาชิก')` |
| กราฟรายได้ 6 เดือน · กราฟ margin | `v_monthly_pl` 6 แถวล่าสุด |
| ตารางรายเดือนย่อ | `v_monthly_pl` |
| Member Credit Alert | `member_balances.next_expiry` ภายใน 30 วัน |

margin คำนวณจาก `profit_cash / net_revenue` ในหน้าเว็บได้ เพราะเป็นการหารเลขสองตัว
ที่ view ให้มาแล้ว ไม่ใช่การนิยามสูตรเงินใหม่

### เส้นทางและการเด้งหน้า

middleware ไม่รู้ role (ต้อง query DB ทุก request) จึงให้ `/` เป็นตัวส่งต่ออย่างเดียว

| เส้นทาง | เนื้อหา | ใคร |
| ------- | ------- | --- |
| `/` | ไม่มีเนื้อหา — redirect ตาม role | ทุกคน |
| `/overview` | หน้าภาพรวมใหม่ | admin · manager |
| `/today` | ยอดวันนี้ (ย้ายเนื้อหามาจาก `/` เดิม) | ทุกคน |

staff เข้า `/` → เด้งไป `/today` · admin/manager → เด้งไป `/overview`
เมนูล่างของพนักงานเปลี่ยนปลายทาง `/` เป็น `/today` เท่านั้น ไม่มีอะไรอื่นเปลี่ยนสำหรับเขา

## เรื่องที่ต้นแบบไม่มีแต่ต้องมี

**แถบเตือน "เดือนนี้ข้อมูลยังไม่ครบ"** — ก.ค. 69 ตอนนี้แสดงกำไรเงินสด 121,175 บาท
ซึ่งสูงกว่าความจริงมาก เพราะค่าเช่าและเงินเดือนบันทึกตอนสิ้นเดือน
หน้า `/finance` มี `isMonthIncomplete()` อยู่แล้ว หน้าภาพรวมต้องใช้ตัวเดียวกัน
ถ้าไม่ใส่ การ์ดใหญ่ที่สุดบนหน้าแรกของเจ้าของร้านจะโชว์กำไรหลอกตาทุกต้นเดือน
(กฎบัญชีข้อ 5 ใน README)

**หมายเหตุ Gowabi/KOL** — กำไรสะสมปีนี้ที่หน้านี้จะแสดงคือ 4,437 บาท ซึ่งต่ำกว่าความจริง
เพราะรายรับ Gowabi 64 รายการ (มูลค่าตั๋ว 44,700) และ KOL 25 รายการ (19,450) บันทึกเป็น 0
(กฎบัญชีข้อ 7 ใน README) หน้านี้ไม่แก้ปัญหานั้น แต่ต้องไม่ทำให้เข้าใจผิดเพิ่ม

## การทดสอบ

`src/lib/chart.ts` เป็นฟังก์ชันบริสุทธิ์ เขียนเทสก่อนตามแบบที่โปรเจกต์ใช้มา เคสที่ต้องมี:

- ข้อมูลว่าง — ไม่ crash ไม่หารศูนย์
- ค่าติดลบ — กำไรเงินสด 3 เดือนแรกติดลบ (−107,695 / −70,428 / −27,606) ต้องวาดใต้เส้นศูนย์ได้
- ค่าเท่ากันหมด — ช่วงเป็นศูนย์ ต้องไม่หารศูนย์
- เดือนขาดหาย — ข้อมูลเริ่ม มี.ค. 69 ถ้าขอ 6 เดือนจะได้ไม่ครบ

`supabase/reconciliation.sql` เพิ่ม 2 ข้อ — `ytd_net_revenue` และ `ytd_profit_cash`
ของเดือน 2026-06 (ตรวจถึง มิ.ย. เพราะ ก.ค. ยังขยับทุกวัน)

ค่าที่ถูกต้อง ตรวจกับฐานข้อมูลจริงแล้ว:

| เดือน | `ytd_net_revenue` | `ytd_profit_cash` |
| ----- | ----------------- | ----------------- |
| 2026-03 | 174,842 | −107,695 |
| 2026-04 | 490,965 | −178,124 |
| 2026-05 | 777,124 | −205,730 |
| **2026-06** | **1,124,141** | **−116,739** |
| 2026-07 (ยังไม่ครบเดือน) | 1,357,668 | 4,437 |

**ระวังตอนทำหน้าจอ:** ตัวเลข YTD ต้องมาจากแถวเดือนเดียวกับ hero เสมอ
ถ้า hero แสดง มิ.ย. แล้ว KPI ข้างล่างแสดง YTD ของ ก.ค. จะกลายเป็นกำไรสะสม +4,437
ทั้งที่ ณ สิ้น มิ.ย. ยังขาดทุนสะสม −116,739 อยู่ — ต่างกัน 121,176 บาท และคนละทิศ
