# วิเคราะห์รายจ่าย — design

วันที่ 27 กรกฎาคม 2569 · หน้าใหม่ `/insights/expenses`

## ปัญหา

เจ้าของร้านเห็นรายจ่ายรวมรายเดือนได้ แต่ตอบไม่ได้ว่า **ต้นทุนกำลังโตหรือลด และเพราะอะไร**
หน้า `/finance` แสดงทีละเดือนและเห็นแค่โครงสร้างคงที่/ผันแปร/ครั้งเดียว
หน้า `/overview` มีกราฟรายได้·รายจ่าย·กำไร 6 เดือน แต่รายจ่ายเป็นก้อนเดียวไม่แยกหมวด

ผลคือความเคลื่อนไหวที่สำคัญมองไม่เห็น ตัวอย่างจากข้อมูลจริง:
เงินเดือนพนักงานประจำโตติดกันทุกเดือน **38,250 → 39,500 → 41,650 → 52,450**
(+37% ใน 3 เดือน) โดยไม่มีหน้าไหนในระบบส่งสัญญาณ

## ผู้ใช้และสิทธิ์

ผู้จัดการขึ้นไป (เหมือนหน้า `/insights/*` อื่น) — ไม่จำกัดเฉพาะ admin
เพราะคนที่ควบคุมค่าใช้จ่ายหน้างานจริงคือผู้จัดการ ถ้าเห็นเองว่าวัสดุสิ้นเปลืองพุ่ง
จะคุมได้โดยไม่ต้องรอเจ้าของร้านสั่ง

## ข้อตกลงที่ผ่านการอนุมัติแล้ว

1. **ลำดับความสำคัญ**: ตอบ *"ทำไมกำไรหด"* ก่อน แล้วตามด้วย *"มีอะไรผิดปกติ"* ·
   *"โครงสร้างต้นทุนสุขภาพดีไหม"* · *"เดือนหน้าตั้งงบเท่าไร"*
2. **ของก้อนใหญ่**: ไม่เพิ่มช่องให้ติ๊ก แต่โชว์ชื่อ 5 รายการใหญ่สุดข้างกราฟ
   ให้ผู้อ่านเข้าใจเองว่ายอดที่พุ่งมาจากรายการเดียว
3. **ไม้บรรทัดต่างกันตามหมวด**: หมวดที่ควรโตตามงานวัดเป็น % ของยอดขาย
   หมวดที่ไม่ควรโตตามงานวัดเป็นบาท
4. **เดือนที่ยังไม่จบ**: เปรียบเทียบช่วงวันเท่ากัน (1–27 ก.ค. เทียบ 1–27 ของเดือนก่อน)
5. **ที่ตั้ง**: หน้าใหม่ในเมนูผู้บริหาร ไม่ยัดเข้าหน้าการเงินหรือหน้ารายงาน
6. **เกณฑ์เตือน**: เปลี่ยนแปลง ≥ 10% **และ** คิดเป็นเงิน ≥ 2,000 บาท/เดือน
7. **ฐานเปรียบเทียบ**: **ค่ากลาง (median) 3 เดือน** ไม่ใช่ค่าเฉลี่ย

### ทำไมต้องเป็นค่ากลาง ไม่ใช่ค่าเฉลี่ย

ทดสอบย้อนหลังกับเดือน มิ.ย. 2569 (เดือนเดียวที่มีประวัติครบ 3 เดือน):

| หมวด | ใช้ค่าเฉลี่ย | ใช้ค่ากลาง | ความจริง |
|---|---|---|---|
| เงินเดือนประจำ | +31.8% 🔴 | **+32.8% 🔴** | โตจริง ต้องเตือน |
| ค่าเช่าสถานที่ | +13.0% 🟡 | **−1.5% เงียบ** | หลอก — เม.ย. จ่ายแค่ 18,000 |
| ค่าน้ำ/ค่าไฟ | +23.5% 🟡 | **−1.1% เงียบ** | หลอก — มี.ค. บันทึกแค่ 2,941 |

ค่ากลางเขี่ยเดือนผิดปกติทิ้งเอง จึงเก็บความไวของเกณฑ์ 10%/2,000 ไว้ได้
โดยไม่ต้องแลกกับสัญญาณหลอก

## เนื้อหาหน้า — 4 บล็อกเรียงตามลำดับความสำคัญ

ตัวเลขตัวอย่างทุกตัวคำนวณจากข้อมูลจริงในระบบ ณ 27 ก.ค. 2569

**การเลือกเดือน**: หน้านี้เปิดมาที่เดือนปัจจุบันเสมอ และมีปุ่มเลื่อนเดือนแบบเดียวกับหน้า
`/finance` (`FinanceMonthHeader`) เลือกเดือนที่ปิดแล้วได้ ตอนนั้นบล็อก 1 จะเทียบเต็มเดือน
ต่อเต็มเดือน (ไม่ตัดวัน) และกลุ่มคงที่จะถูกนำมาตรวจเตือนด้วย

**บล็อก 1 กับบล็อก 2 ใช้ฐานเปรียบเทียบคนละตัวโดยตั้งใจ** — บล็อก 1 ตอบว่า
*"ต่างจากคราวที่แล้วเพราะอะไร"* จึงเทียบกับเดือนก่อนหน้าเดือนเดียว ส่วนบล็อก 2 ตอบว่า
*"ผิดปกติไหม"* จึงต้องเทียบกับค่ากลาง 3 เดือน ตัวเลข % ของสองบล็อกจึงไม่เท่ากันเป็นเรื่องปกติ
หน้าเว็บต้องเขียนกำกับไว้ทั้งสองที่ว่ากำลังเทียบกับอะไร

### บล็อก 1 — เดือนนี้ต่างจากปกติเพราะอะไร

หัวเรื่องสรุป: ช่วงวันที่ดู · รายจ่ายรวม · ส่วนต่างเทียบช่วงเดียวกันเดือนก่อน (บาทและ %) ·
รายได้และส่วนต่างของรายได้ (ต้องมีคู่กันเสมอ ไม่งั้นตีความรายจ่ายผิด)

```
1–27 ก.ค. 69   เทียบช่วงเดียวกันเดือนที่แล้ว
รายจ่าย 118,562 ฿   ↓ 25,379 ฿  (−17.6%)
รายได้  322,242 ฿   ↑ 5,454 ฿   (+1.7%)
```

ถัดมาเป็นแถบแยกตามหมวด เรียงตามขนาดผลกระทบ (ค่าสัมบูรณ์) จากมากไปน้อย
แถบไปทางซ้าย = ลดลง ทางขวา = เพิ่มขึ้น:

```
อื่นๆ                 −21,625
วัสดุ-สิ้นเปลือง       −8,509
ซักรีด                 −2,400
ค่าน้ำ/ค่าไฟ           −1,181
ค่าเช่าสถานที่         +2,500
ค่ามือหมอ             +4,835
```

ปิดท้ายด้วย **5 รายการใหญ่สุดของช่วงที่ดู** (ชื่อรายการ + จำนวนเงิน) —
นี่คือกลไกที่ทำให้ของก้อนเดียวอธิบายตัวเองโดยไม่ต้องติ๊กอะไร
เดือน มิ.ย. จะเห็น "ค่าช่างพี่ต้อม ทำประตู เดินท่อ 23,000" ซึ่งอธิบายส่วนต่าง −21,625 ได้ทันที

### บล็อก 2 — มีอะไรผิดปกติบ้าง

การ์ดเตือนเฉพาะหมวดที่เข้าเกณฑ์ครบทุกข้อ แต่ละใบต้องมี 4 อย่าง:
ชื่อหมวด · ตัวเลขจริงกับค่าปกติ · ส่วนต่าง · **เงินที่ประหยัดได้ถ้ากลับไปเท่าค่าปกติ**
(บรรทัดสุดท้ายคือตัวที่ทำให้ตัดสินใจได้ ไม่ใช่แค่รู้)

ถ้าไม่มีหมวดไหนเข้าเกณฑ์ ให้ขึ้นข้อความ "ตอนนี้ไม่มีหมวดไหนผิดปกติ" —
ห้ามซ่อนบล็อกทิ้ง เพราะการเห็นว่า "ตรวจแล้วไม่มีอะไร" คือข้อมูล ไม่ใช่ความว่างเปล่า

สถานะ ณ วันเขียน spec: ไม่มีการ์ดเตือน ทุกหมวดอยู่ในเกณฑ์ปกติหรือดีกว่าปกติ
(วัสดุ 2.44% เทียบค่าปกติ 4.19% · ซักรีด 1.55% เทียบ 3.84% · ค่ามือ 40.66% เทียบ 40.59%)

### บล็อก 3 — ทุก 100 บาทที่ขายได้ หายไปไหน

แถบสัดส่วนของเดือนที่ปิดแล้วล่าสุด แจกแจงว่าขายได้ 100 บาทหมดไปกับหมวดใดกี่บาท
และเหลือกำไรกี่บาท ตามด้วยกราฟเส้น "ต้นทุนรวมต่อรายได้ 100 บาท" ย้อนหลังทุกเดือนที่มีข้อมูล

```
มี.ค. 161.6 → เม.ย. 122.3 → พ.ค. 109.6 → มิ.ย. 86.7
                                          ↑ เดือนแรกที่ต่ำกว่า 100 = เริ่มมีกำไร
```

### บล็อก 4 — เดือนหน้าควรตั้งงบเท่าไร

ตารางหมวด × เดือน ย้อนหลังทุกเดือนที่มีข้อมูล พร้อมคอลัมน์ค่ากลางและลูกศรแนวโน้ม
ปิดท้ายด้วยบรรทัดประมาณการรายจ่ายทั้งเดือนปัจจุบัน

ลูกศรแนวโน้มตัดสินจากทิศทางของ 3 เดือนล่าสุด **ที่ปิดแล้ว** (ไม่นับเดือนปัจจุบัน
เพราะยอดยังไม่ครบ จะได้ลูกศรลงทุกหมวดเสมอ): ขึ้นติดกัน 3 เดือน = ↗ ·
ลงติดกัน 3 เดือน = ↘ · นอกนั้น = → · มีข้อมูลไม่ถึง 3 เดือนที่ปิดแล้ว = ไม่แสดงลูกศร

เดือนปัจจุบันยังมีคอลัมน์ของตัวเองในตาราง แต่ต้องมีป้ายกำกับว่ายังไม่จบ

**ประมาณการสิ้นเดือน** = ยอดที่บันทึกแล้วในเดือนปัจจุบัน
\+ หมวดประจำที่ยังไม่ถูกบันทึกในเดือนนี้ (ใช้ค่ากลาง 3 เดือนของหมวดนั้น)
ต้องมีข้อความกำกับเสมอว่าเป็นการประมาณ และบอกว่าประมาณจากหมวดใดบ้าง

## ไม้บรรทัด — หมวดถูกแบ่งเป็น 3 กลุ่ม

| กลุ่ม | หมวด | วัดด้วย | ช่วงที่ตรวจ |
|---|---|---|---|
| โตตามงานได้ | ค่ามือหมอ · วัสดุ-สิ้นเปลือง · ซักรีด | % ของยอดขาย | ช่วงวันปัจจุบัน (สดทุกวัน) |
| ไม่ควรโตตามงาน | ค่าเช่าสถานที่ · เงินเดือนพนักงานประจำ · ค่าน้ำ/ค่าไฟ/Internet | บาท | เฉพาะเดือนที่ปิดแล้ว |
| ตั้งใจจ่ายเอง | การตลาด/โฆษณา · อื่นๆ · ชุดลูกค้าชุดหมอชุดพนักงาน | บาท | แสดงอย่างเดียว ไม่เตือน |

**ทำไมกลุ่มคงที่ตรวจเฉพาะเดือนที่ปิดแล้ว** — ค่าเช่าและเงินเดือนจ่ายเป็นก้อนวันที่ตายตัว
การเทียบช่วง 1–27 จึงไร้ความหมาย (ทั้ง มิ.ย. และ ก.ค. ช่วง 1–27 มีเงินเดือน 0 บาทเท่ากัน
เพราะจ่ายวันที่ 30) ส่วนวัสดุสิ้นเปลืองซื้อกันทุกวัน จับสดได้และยังแก้ทัน

**ค่ามือหมอใช้ยอดที่เกิดขึ้นจากงานจริง ไม่ใช่ยอดที่จ่ายออก** — อ่านจาก `v_therapist_daily`
ไม่ใช่จากแถวรายจ่าย เพราะยอดจ่ายขึ้นกับว่างวดไหนตกวันไหน ซึ่งไม่ได้บอกอะไรเรื่องต้นทุน

### เงื่อนไขการเตือน — ต้องครบทุกข้อ

1. หมวดนั้นอยู่ในกลุ่ม "โตตามงานได้" หรือ "ไม่ควรโตตามงาน"
2. มีประวัติครบ **3 เดือน** (ไม่ครบ = ไม่ตัดสิน ไม่ใช่ตัดสินว่าปกติ)
3. เปลี่ยนแปลงจากค่ากลาง **≥ 10%**
4. คิดเป็นเงิน **≥ 2,000 บาท/เดือน**

ระดับสี: ≥ 10% = 🟡 · ≥ 30% = 🔴 · ต่ำกว่าค่ากลาง ≥ 10% = 🟢
เกณฑ์เงิน 2,000 บาทใช้กับทุกระดับรวมทั้ง 🟢 (ประหยัดได้ไม่ถึง 2,000 ไม่ต้องชม)
🟢 แสดงในบล็อก 2 ได้แต่ต้องอยู่ใต้การ์ดเตือน ไม่แย่งที่ของเรื่องที่ต้องแก้

ไม่ต้องทำ view) · `v_daily_summary` สำหรับรายได้รายวัน · `v_therapist_daily` สำหรับค่ามือรายวัน

### หน้าตาฟังก์ชันใน expense-analytics.ts

```ts
export type Ruler = "revenue_linked" | "fixed" | "discretionary"
export function rulerOf(category: string): Ruler

export function median(values: number[]): number

export type ExpenseRow = {
  expense_date: string   // "2026-07-15"
  category: string
  item: string
  amount: number
}

export type CategoryDelta = {
  category: string
  ruler: Ruler
  /** บาท หรือ % ของยอดขาย ตาม ruler */
  current: number
  baseline: number
  /** ผลเป็นเงินต่อเดือน ใช้ตัดสินเกณฑ์ 2,000 และใช้เขียนบรรทัด "ประหยัดได้เท่าไร" */
  impactBaht: number
  deltaPct: number
  level: "ok" | "better" | "warn" | "alert" | "unknown"
}

/** บล็อก 1 — เทียบกับเดือนก่อนหน้าเดือนเดียว ช่วงวันเท่ากัน */
export function compareRange(input: {
  rows: ExpenseRow[]
  revenueByDate: Map<string, number>
  commissionByDate: Map<string, number>
  month: string        // "2026-07"
  throughDay: number   // 27 = ดูถึงวันที่ 27 · เดือนที่ปิดแล้วส่ง 31
}): {
  current: { expense: number; revenue: number }
  previous: { expense: number; revenue: number }
  byCategory: { category: string; deltaBaht: number }[]   // เรียงตาม |deltaBaht| มาก→น้อย
  topItems: { item: string; amount: number }[]            // 5 อันดับแรกของช่วงปัจจุบัน
}

/** บล็อก 2 — เทียบกับค่ากลาง 3 เดือน ตามไม้บรรทัดของแต่ละหมวด */
export function detectAnomalies(input: {
  rows: ExpenseRow[]
  revenueByDate: Map<string, number>
  commissionByDate: Map<string, number>
  month: string
  throughDay: number
  monthClosed: boolean   // false = ข้ามการตรวจกลุ่ม fixed
}): CategoryDelta[]

/** บล็อก 3 + 4 — อนุกรมรายเดือนแยกหมวด + สัดส่วนต่อรายได้ + ลูกศรแนวโน้ม */
export function monthlySeries(input: {
  rows: ExpenseRow[]
  revenueByMonth: Map<string, number>
  commissionByMonth: Map<string, number>
}): {
  months: string[]
  byCategory: {
    category: string
    amounts: number[]           // เรียงตาม months
    median3: number | null      // null = ข้อมูลไม่ถึง 3 เดือนที่ปิดแล้ว
    trend: "up" | "down" | "flat" | null
  }[]
  costPer100Revenue: number[]   // บล็อก 3 กราฟเส้น
}

/** บรรทัดประมาณการสิ้นเดือน */
export function projectMonthEnd(input: {
  rows: ExpenseRow[]
  month: string
  throughDay: number
}): { total: number; assumedCategories: string[] }
```

### จุดเปราะที่รู้อยู่และวิธีกัน

ชื่อหมวดแก้ได้จากหน้าตั้งค่า ถ้ามีคนเปลี่ยนชื่อหมวด การจับคู่หมวด→ไม้บรรทัดจะหลุด
**หมวดที่จับคู่ไม่ได้ให้ตกไปกลุ่ม `discretionary` (ไม่เตือน) เสมอ** —
เห็นตัวเลขครบแต่ไม่เตือน ดีกว่าเตือนผิดด้วยไม้บรรทัดผิดอัน
และ `rulerOf` ต้องจับคู่ด้วยคำขึ้นต้น ไม่ใช่ชื่อเต็ม (หมวดค่ามือชื่อ
`HR / payroll (ค่ามือหมอ)` ซึ่งเคยถูกเปลี่ยนชื่อมาแล้วเมื่อ 27/7/2569)

### เทสที่ต้องมี

- `median` กับ 2 / 3 / 4 ค่า และค่าซ้ำกัน
- หมวดที่มีประวัติไม่ถึง 3 เดือน → `level: "unknown"` ไม่ใช่ `"ok"`
- ยอดขายเป็น 0 ในช่วงที่ดู → ไม่หารด้วยศูนย์
- ค่าที่อยู่ตรงเส้นเกณฑ์พอดี (10.0% และ 2,000 บาท) → ต้องนับว่าเข้าเกณฑ์
- เข้าเกณฑ์ % แต่เงินไม่ถึง และ เข้าเกณฑ์เงินแต่ % ไม่ถึง → ต้องไม่เตือนทั้งคู่
- เดือนที่ยังไม่จบ → ตัดวันให้ตรงกันทั้งสองฝั่ง (เดือน 31 วันเทียบเดือน 30 วันต้องไม่เพี้ยน)
- หมวดชื่อไม่รู้จัก → ตกกลุ่ม discretionary
- ค่ามือหมออ่านจาก `v_therapist_daily` ไม่ใช่จากแถวรายจ่าย
- เคสจริงเดือน มิ.ย. 2569: เงินเดือนประจำต้องเตือน 🔴 ส่วนค่าเช่าและค่าน้ำค่าไฟต้องเงียบ

## สิ่งที่ไม่ทำในรอบนี้

- ช่องติ๊ก "รายการนี้เป็นการลงทุน" — ตกลงกันแล้วว่าใช้วิธีโชว์ชื่อรายการใหญ่แทน
  ถ้าใช้ไปสักพักแล้วยังอยากได้เส้นแยก ค่อยเติมทีหลังโดยไม่ต้องรื้อ
- ตั้งงบต่อหมวดแล้วเทียบงบจริง — ต้องมีคนตั้งงบก่อน ยังไม่มีข้อมูลนั้น
- เทียบปีต่อปี — มีข้อมูลแค่ 5 เดือน ยังเทียบไม่ได้
- แจ้งเตือนเข้าไลน์เมื่อหมวดไหนพุ่ง — รอดูก่อนว่าเกณฑ์นิ่งจริงไหม
- แก้ป้ายคงที่/ผันแปร/ครั้งเดียวที่ปนกันอยู่ในตาราง `expenses.cost_type` —
  หน้านี้ไม่ได้ใช้ป้ายนั้นเลย ใช้การจับคู่หมวดของตัวเองแทน

## ข้อจำกัดที่ต้องบอกผู้ใช้บนหน้าเว็บ

- มีข้อมูลแค่ 5 เดือน (มี.ค.–ก.ค. 2569) หมวดที่ประวัติไม่ครบ 3 เดือนจะยังไม่ถูกตัดสิน
- เดือน มี.ค. บันทึกไม่ครบทุกหมวด (ค่าน้ำค่าไฟมีแค่ 2,941 บาท) — ค่ากลางกันผลกระทบไว้แล้ว
  แต่ตัวเลข มี.ค. ในตารางยังต่ำกว่าความจริง
- การเทียบช่วงวันยังเพี้ยนได้ถ้าเดือนหนึ่งจ่ายค่าเช่าวันที่ 5 อีกเดือนจ่ายวันที่ 28
  จึงต้องมีป้ายกำกับว่ากำลังดูแบบเทียบช่วงวัน และกลุ่มคงที่ถูกกันออกจากการเตือนช่วงวันอยู่แล้ว
