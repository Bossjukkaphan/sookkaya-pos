# เช็คอินเข้างาน + สถานะนวด/ชำระ/จับเวลาบนบอร์ดคิว

**เป้าหมาย:** (1) หน้า /checkin บันทึกเข้างานรายวันทั้งร้าน — หมอไม่มา = ปิดรับคิวหมอคนนั้นทั้งจองไลน์และหน้าร้าน (2) บอร์ดคิวแสดงสถานะนวด 3 ขั้น + ชิพชำระเงินแยกอิสระ + จับเวลาสด ตามภาพตัวอย่าง ThaiHand

## 1. หน้า /checkin (เมนู "เข้างาน")

- ดูได้ 3 วันหลัก: เมื่อวาน ← วันนี้ → พรุ่งนี้ (ลูกศรเลื่อนวันอิสระ + ปุ่มวันนี้)
- 2 กลุ่ม: **หมอนวด** (จาก therapists active) และ **พนักงาน** (ตารางใหม่ staff_members: ผู้จัดการ/ผู้ช่วยผู้จัดการ/พ่อบ้าน — เพิ่ม/ปิดคนได้ในหน้านี้เลย)
- ต่อคน: ปุ่มสลับ มา (วงเขียว + เวลาเช็คอิน) / ไม่มา (วงแดง) · กดเช็คเอาต์ได้ (เก็บเวลาออก) · สรุปหัวหน้า "วันนี้มา X/Y คน"
- ต่อคนโชว์ "เดือนนี้มา N วัน" (ฐานข้อมูลเงินเดือน/OT ในอนาคต)
- ปุ่มลัด "ไปหน้าคิววันนี้"
- **เช็คอินพรุ่งนี้ = แผนล่วงหน้า** — ใช้คุมสลอตจองไลน์ของพรุ่งนี้ด้วย

## 2. ข้อมูล

- `staff_members` (id, name, role text, is_active, sort) — RLS authenticated
- `attendance` (id, work_date, therapist_id nullable, staff_id nullable, checked_in_at, checked_out_at, created_by) — unique ต่อคนต่อวัน + check ว่ามี therapist_id หรือ staff_id อย่างใดอย่างหนึ่ง — RLS authenticated
- ไม่มีแถว = ยังไม่เช็คอิน (ค่าเริ่มต้นทุกวัน)

## 3. ผลต่อการรับคิว

- **จองไลน์:** วันที่มีข้อมูลเช็คอินแล้ว (วันนี้/พรุ่งนี้ที่ติ๊กล่วงหน้า) — รีเควสหมอที่ไม่ได้เข้างานวันนั้นถูกปฏิเสธพร้อมข้อความแนะนำ (ความจุรวมยังคุมด้วยการกดรับ/ปฏิเสธของร้านตามเดิม) · วันที่ยังไม่มีข้อมูล = เปิดปกติ
- **หน้าร้าน (บอร์ด):** แถวหมอที่ไม่เช็คอิน (วันนี้) = อวตารวงแดง + พื้นลายทแยง + ลาก/วางการ์ดใส่ไม่ได้ (บล็อกฝั่งหน้าจอ) · แอดมินแก้เช็คอินย้อนหลังได้ถ้าหมอมาสาย

## 4. สถานะบนการ์ดคิว (ไม่แตะ schema — คำนวณจากข้อมูลที่มีอยู่)

การ์ดมี **2 ชิพอิสระ** ตามภาพ:

| ชิพนวด | เงื่อนไข (คำนวณจากเวลา ณ ตอนนี้) |
|---|---|
| รอเริ่ม (ขาว) | ยังไม่กดเริ่ม และยังไม่ถึง/เพิ่งถึงเวลา |
| กำลังนวด (ม่วง) | กด "เริ่มบริการ" แล้ว หรือการ์ดจ่ายแล้วที่อยู่ในช่วงเวลานวด |
| เสร็จสิ้น (เขียว) | เลยเวลาจบ (เริ่ม+ระยะเวลา) — **เปลี่ยนเองอัตโนมัติ** ไม่ต้องกด ไม่ต้องมี cron (บอร์ดเดินนาฬิกาทุกนาทีอยู่แล้ว) |

| ชิพจ่าย | เงื่อนไข |
|---|---|
| ชำระแล้ว (เขียว) | การ์ดผูกบิลแล้ว (sale_id) |
| รอชำระ (เหลือง เตือน) | เสร็จสิ้นแล้วแต่ยังไม่ผูกบิล |

- ระหว่างกำลังนวด **แก้การ์ดได้ตลอด** (ต่อเวลา/เปลี่ยนเมนู — เวลาจบขยับ สถานะคงกำลังนวดต่อ) · หลังจ่ายแล้วแก้ผ่านบิลในยอดวันนี้ (sync ลงคิวอัตโนมัติ มีอยู่แล้ว)
- status ในฐานข้อมูลคงเดิมทั้งหมด (waiting / in_service / paid / ...) — "เสร็จสิ้น" เป็นการแสดงผล จึงเข้ากันได้กับการ์ดเก่าทุกใบและ flow POS เดิม 100%

## 5. จับเวลาสด (มุมการ์ด) + หัวบอร์ด

- กำลังนวด: เหลือ X นาที (ม่วง) · เลยเวลาจบแต่ยังไม่จ่าย: ⏳ เกิน X นาที (แดง) · รอเริ่มแต่เลยเวลานัด: เตือนแดงเช่นกัน
- หัวบอร์ด: "ว่าง N คน · ว่าง N เตียง" สด (หมอเช็คอินที่ไม่มีคิวช่วงนี้ / เตียงไม่ถูกใช้)

## 6. ทดสอบ

- lib ใหม่ `queue-status.ts` (TDD): ตารางเงื่อนไข 2 ชิพ + นาทีเหลือ/เกิน ครบทุกกรณี (รวมการ์ดเก่า status=paid)
- มือ: เช็คอิน → แถวเขียว/แดง → จองไลน์สลอตลด → เริ่มบริการ → ครบเวลาเปลี่ยนเสร็จสิ้นเอง → รอชำระเหลือง → เก็บเงิน → ชำระแล้ว

## ไม่ทำรอบแรก

เงินเดือน/OT จากชั่วโมงงาน · หมอเช็คอินเอง · ตารางกะล่วงหน้ารายสัปดาห์ · บังคับฝั่ง server กันวางการ์ดใส่หมอไม่มา (เครื่องมือภายใน บล็อกฝั่งจอพอ)
