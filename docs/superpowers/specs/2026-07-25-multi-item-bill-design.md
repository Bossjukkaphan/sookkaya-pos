# บิลหลายรายการ (บิลชุด) — ลูกค้า 1 คน หลายบริการใน 1 บิล

**ปัญหา:** ลูกค้าทำนวด 2+ รายการต้องเปิด 2 บิล (เคสจริง: คุณตั้มทำ 2 รายการ) — พนักงานกรอกซ้ำ ลูกค้าเห็นใบเสร็จแยก

**แนวทางที่เลือก (A "บิลชุด"):** ทุกรายการยังเป็นแถวขายของตัวเอง (สูตรค่ามือ/โปร/รายงานเดิมไม่แตะ) แต่ผูกกันด้วย `bill_id` เดียว จ่ายครั้งเดียว แสดงรวมเป็นใบเดียว — แบบเดียวกับกลไกบิลกลุ่มที่พิสูจน์แล้ว

**ตัดสินใจแล้ว:** ส่วนลด/โปรคิด**ต่อรายการ** (Happy Hour, % ทำงานต่อเมนูใครเมนูมัน) · เวลาคิวหลายรายการ**ไล่ต่อเนื่องอัตโนมัติ** แก้ได้ · จ่ายเงิน**วิธีเดียวทั้งบิล**

## 1. ข้อมูล

- migration: `alter table sales add column bill_id uuid` + index `(bill_id)` · ว่าง = บิลรายการเดียวแบบเดิม (ข้อมูลเก่าไม่ต้องย้าย)
- เลขบิลที่โชว์ = `receipt_no` ของรายการแรก (ทุกแถวยังมีเลขใบเสร็จเฉพาะตัวตาม trigger เดิม)
- กติกา: ทุกแถวใน bill_id เดียวกันต้องมี sale_date, customer, payment_method ตรงกัน (ตรวจใน reconciliation ข้อใหม่)

## 2. หน้าบันทึกขายตรง (pos-form)

- state เปลี่ยนจากรายการเดียวเป็น `items[]` (เมนู, หมอ, โปร/ส่วนลด, รีเควส ต่อรายการ) — เริ่ม 1 รายการ หน้าตาเดิม
- ปุ่ม "+ เพิ่มรายการ" ต่อท้าย · ลบรายการได้ (เหลืออย่างน้อย 1)
- ลูกค้า/เวลาใช้บริการ/ที่มา/วิธีจ่าย/เตียง กรอกครั้งเดียวใช้ร่วมทั้งบิล · สรุปยอดท้ายฟอร์มรวมทุกรายการ
- submit: ถ้า >1 รายการ สร้าง `bill_id = crypto.randomUUID()` แล้วเรียก `createSale` ต่อรายการพร้อม bill_id (แบบเดียวกับ GroupPosForm) · toast โชว์เลขบิลแรก + ยอดรวม · รายการหลังพังกลางทาง → แจ้งรายการที่สำเร็จ/ล้มเหลวชัดเจน

## 3. ฝั่งจองคิว (queue-form-dialog)

- ปุ่ม "+ เพิ่มรายการ" ใน dialog เพิ่มคิว → หลายบริการของลูกค้าคนเดียว
- สร้างการ์ดคิว 1 ใบต่อบริการ (บอร์ดเดิมไม่เปลี่ยน) เวลาเริ่มรายการถัดไป = เวลาเริ่มก่อนหน้า + duration (แก้ได้ก่อนบันทึก)
- การ์ดชุดผูกกันด้วย `queue_entries.group_id` (กลไกกลุ่มเดิม) → เก็บเงินผ่านจอรวมเดิม (GroupPosForm)
- GroupPosForm: ถ้าทุกรายการในกลุ่มเป็นลูกค้าคนเดียวกัน → ใส่ bill_id เดียวตอนบันทึก

## 4. แสดงผล/แก้ไข

- ยอดวันนี้ + ประวัติบิล: แถว bill_id เดียวกันรวมเป็นใบเดียว (ยอดรวม, จำนวนรายการ) กางดูรายรายการ · helper `groupSalesByBill()` ใน lib (TDD)
- แก้ไขทีละรายการด้วย dialog เดิม (sync คิวต่อรายการทำงานต่อ) · ลบทีละรายการ หรือทั้งบิล (ยืนยันก่อน)

## 5. ไม่ทำ (YAGNI)

- ไม่ทำตาราง bills แยก · ไม่รวมส่วนลดเป็นก้อนท้ายบิล · ไม่แตะ sale-math.ts/views · ไม่ทำใบเสร็จพิมพ์รวม (ยังไม่มีระบบพิมพ์)

## 6. ทดสอบ

- unit: groupSalesByBill (รวม/ยอด/ลำดับ), เวลาไล่ต่อเนื่อง (ข้ามเที่ยงคืนไม่ต้องรองรับ — ร้านปิดก่อน), reconciliation ข้อใหม่
- มือ: จองคิว 2 รายการ → การ์ด 2 ใบเวลาไล่กัน → เก็บเงินรวม → ยอดวันนี้เห็นใบเดียว → แก้ 1 รายการ → คิว sync → ค่ามือหมอถูก
