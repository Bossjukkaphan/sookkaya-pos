## วิธีวัดผล

วัดจาก POS โดยตรง ไม่ต้องพึ่งสถิติของ LINE:

- **ตัวชี้วัดหลัก** — จำนวนบิลของวันที่ยิง เทียบค่าเฉลี่ยวันเดียวกันย้อนหลัง 8 สัปดาห์
- **ตัวชี้วัดรอง** — จำนวน `queue_entries` ที่ `booking_channel = 'line'` และ `created_at`
  (เวลาไทย) อยู่ระหว่าง 09:00–14:00 ของวันนั้น เทียบกับค่าเฉลี่ยของวันเดียวกัน
- **ตัวชี้วัดกันพลาด** — `turn_aways` ของวันนั้นต้องไม่เพิ่ม

**เกณฑ์ผ่าน:** วันธรรมดา ≥ 20 บิล (จากฐาน ~16) · วันเสาร์ ≥ 26 บิล (จากฐาน 23.3)

**ถ้าไม่ผ่านทั้งนัดที่ 1 และ 2:** หยุดยิงนัดที่ 3–4 ตามแผนเดิม แล้วกลับมาคุยเรื่องส่วนลด
(ขยาย Happy Hours เป็น 10:00–14:00 คือไพ่ที่ข้อมูลหนุนที่สุด) — อย่ายิงข้อความเดิมซ้ำ

## ความเสี่ยง

- **ลูกค้าบล็อก/เลิกติดตาม** — 4 ครั้งใน 14 วัน (เฉลี่ยทุก 3.5 วัน) อยู่ในเกณฑ์ปกติ
  ให้เช็คทาร์เก็ตรีชใน OA Manager หลังนัดที่ 2 ถ้าลดเกิน 3% ให้ทบทวนความถี่
- **โควตาหมดก่อนสิ้นเดือน** — เช็ค `get_message_quota` ก่อนยิงทุกครั้ง ถ้าคงเหลือ < 1,300
  ให้ข้ามนัดนั้นไป การส่งไลน์รายคนใน `/crm` สำคัญกว่า broadcast ซ้ำ
- **ยิงผิดเวลา** — ทั้ง 4 นัดยิงมือผ่าน OA Manager ยังไม่มี automation จึงต้องมีคนกดจริงเวลา 09:00

## สิ่งที่จงใจไม่ทำรอบนี้

- ไม่ทำ automation ตั้งเวลายิงอัตโนมัติ — 4 ครั้งไม่คุ้มกับการเขียน cron และความเสี่ยงยิงผิด
- ไม่แบ่งกลุ่มผู้รับ (audience segmentation) — ทางเทคนิคทำได้ (ทาร์เก็ตรีช 1,225 เกินขั้นต่ำ
  ของ LINE) แต่ไม่คุ้ม: การแบ่งตามข้อมูลประชากรของ LINE ครอบคลุมผู้ใช้ไทยไม่ทั่วถึง ทำให้
  ผู้รับจริงหดลงโดยคาดเดาไม่ได้ ส่วนการทำ audience จาก user ID ก็ได้แค่ 80 คนที่ผูกใน POS
  ซึ่งกลุ่มนั้นส่งรายคนผ่าน `/crm` ได้อยู่แล้วโดยไม่ต้องเปลือง broadcast
- ไม่แตะเทมเพลตใน `src/lib/crm.ts` — เป็นสำนวนที่ Boss เขียนเอง
