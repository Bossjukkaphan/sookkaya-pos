# ยอดรวมเทียบ ThaiHand บนหน้ายอดขาย (/today)

**วันที่:** 2026-08-10 · **สถานะ:** อนุมัติแล้ว

## ปัญหา

ตอนเทียบยอดรายวันระหว่าง POS เรากับจอ ThaiHand เลขหัวใหญ่ของ ThaiHand
("รายรับทั้งหมด" เช่น 17,360) ไม่มีบนหน้า `/today` — ต้องเอา Volume + เติมเงินสมาชิก
มาบวกเองทุกครั้ง เลขอื่นทุกตัว (Volume, เครดิตที่ตัด, เงินเข้าจริง, ส่วนลด, ค่ามือ)
มีบนหน้าอยู่แล้วและตรงกัน

## สิ่งที่ทำ

เพิ่ม **หนึ่งบรรทัด** ท้ายการ์ดเขียว (รายรับ) ในหน้า `/today` ต่อจากบรรทัด
"เติมเงินสมาชิกวันนี้":

```
= รายรับที่รับรู้              10,665
เติมเงินสมาชิกวันนี้           5,000
────────────────────────────
ยอดรวมเทียบ ThaiHand ⓘ    17,360
```

## นิยาม

```
ยอดรวมเทียบ ThaiHand = totalVolume + totalTopup
```

- `totalVolume` — ยอดรับจริง (Volume) จาก `v_daily_summary` (มีบนหน้าแล้ว)
- `totalTopup` — เงินเติมสมาชิก (`member_topups.cash_received`) ในช่วงที่เลือก (มีบนหน้าแล้ว)
- ตรงกับสูตรของ ThaiHand: รายรับจากการใช้บริการ + ยอดขายแพ็กเกจ

บวกในหน้า `/today` ตรง ๆ (แนวทาง A) — ไม่แตะ DB view, ไม่มี helper ใหม่
เหตุผล: เป็นการบวกยอดรายวันสองตัวที่ audit แล้ว ตาม idiom เดิมของหน้า
(เช่น `grossProfit`, `bonusUsedTotal` ก็ derive บนหน้าแบบเดียวกัน)
ถ้าวันหน้าต้องใช้ใน LINE daily report หรือ `/reports` ค่อยยกนิยามไป view (YAGNI)

## รายละเอียด UI

- ตำแหน่ง: บรรทัดสุดท้ายของการ์ดเขียว มีเส้นคั่น (`border-t`) ด้านบน
- สี: ตัวเลขโทน slate (เทา) ไม่ใช่เขียว — สื่อว่าเป็นเลขอ้างอิงสำหรับเช็คยอด ไม่ใช่รายได้
- InfoDot (เพิ่มข้อความใน `src/lib/money-info.ts`):
  "Volume + เติมเงินสมาชิก — ให้ตรงกับช่อง 'รายรับทั้งหมด' บนจอ ThaiHand
  ใช้เช็คยอดสองระบบเท่านั้น ไม่ใช่รายได้ (แพ็กเกจจะถูกนับซ้ำตอนลูกค้ามาใช้เครดิต)"
- แสดงทั้งโหมดวันเดียวและช่วงหลายวัน (ยอดรายวันทั้งคู่บวกข้ามวันได้ ไม่โดน ROW_CAP)
- ไม่มีเงื่อนไขซ่อน: วันไม่มีเติมเงิน เลขเท่ากับ Volume ซึ่งยังตรงกับ ThaiHand

## สิ่งที่ไม่ทำ

- ไม่แก้ `v_daily_summary` หรือ view ใด ๆ — ไม่ต้องรัน reconciliation รอบใหม่
- ไม่แตะเลขหลักสองตัวเดิม: รายรับที่รับรู้ (`net_revenue`) และเงินเข้าจริง (`cash_in`)
  ยังเป็นพระเอกของหน้าเหมือนเดิม
- ไม่เพิ่มใน LINE daily report / หน้า `/reports` (รอบนี้)

## การตรวจรับ

- เปิด `/today` วันที่ 10 ส.ค. 2026 ต้องเห็น "ยอดรวมเทียบ ThaiHand 17,360"
  ตรงกับจอ ThaiHand วันเดียวกัน
- เลขเดิมทุกตัวบนหน้าไม่เปลี่ยน

# ภาคต่อ 2026-08-11: ย้ายยอดเงินหน้า `/reports` ไปใช้ view

## ปัญหาที่เจอตอนตรวจย้อน

หน้า `/reports` บวกยอดเงินจากแถว `sales` ดิบ โดยไม่ใส่ `.limit()` และไม่มีป้ายเตือน
PostgREST ตัดแถวให้เองเงียบๆ ทุกยอดในการ์ดเขียวจึงต่ำกว่าจริงเมื่อช่วงที่เลือกมีบิลเกินเพดาน

วัดจริงกับข้อมูลร้าน: ช่วง 60 วัน = 1,115 บิล → Volume ที่ควรเป็น 776,399฿ จะโชว์ 692,768฿
**ขาด 83,631฿ (10.8%)** และ "ยอดรวมเทียบ ThaiHand" ที่เพิ่งเพิ่มก็รับปัญหานี้มาด้วย
ปุ่มสำเร็จรูปทุกปุ่มปลอดภัย (เดือนหนึ่ง ~430–570 บิล) เจอเฉพาะช่วงที่กรอกเองยาวเกิน ~55 วัน

## สิ่งที่แก้

ย้ายทุกตัวที่มีคอลัมน์ใน `v_daily_summary` ไปอ่านจาก view (view คืนวันละแถว ไม่ชนเพดาน):

| ตัวเลข | เดิม | ใหม่ |
|---|---|---|
| รายรับที่รับรู้ | `sum(rows.revenue_recognize)` | `sum(v.net_revenue)` |
| ยอดรับจริง (Volume) | `sum(rows.net_amount)` | `sum(v.volume)` |
| ส่วนลดที่ให้ | `sum(rows.discount)` | `sum(v.discount_total)` |
| เครดิตแถมสมาชิก | `sum(rows.bonus_used)` | `volume − net_revenue` (สูตรเดียวกับ `/today`) |
| จำนวนบิล | `rows.length` | `sum(v.sessions)` |
| กราฟยอด/บิลรายวัน | บวกจาก rows | ต่อแถวจาก view ตรงๆ |
| ยอดรวมเทียบ ThaiHand | Volume(rows) + เติมเงิน | Volume(view) + เติมเงิน |

ที่ยังอิงรายบิลเพราะไม่มี view รองรับ: เมนูขายดี · ส่วนลดตามโปร · ช่วงเวลา ·
ช่องทางการจอง · ลูกค้า · เครดิตสมาชิกที่ใช้ (`credit_used`)

**ตรวจว่าโดนตัดไหมด้วย `{ count: "exact" }`** เทียบจำนวนจริงในฐานข้อมูลกับจำนวนแถวที่ได้มา
ไม่ผูกกับค่าคงที่ `ROW_CAP` เพราะถ้าเพดานฝั่งเซิร์ฟเวอร์ถูกตั้งต่ำกว่าที่เดา การเทียบ
`length === ROW_CAP` จะกลับไปเงียบอีกแบบหนึ่ง เมื่อโดนตัดจะขึ้นป้ายเหลืองบอกชัดว่า
ยอดเงินยังครบ แต่ส่วนแยกรายบิลนับได้แค่กี่บิล

เปอร์เซ็นต์ในบล็อก "ช่องทางการจอง" หารด้วย `rows.length` ไม่ใช่ `totalBills`
เพราะตัวเศษมาจาก rows — ไม่งั้นตอนโดนตัดเปอร์เซ็นต์จะรวมกันไม่ถึง 100

## หลักฐานการตรวจรับ

เทียบผลลัพธ์แบบใหม่กับความจริงจากตาราง `sales` ตรงๆ ในช่วง 60 วัน (SQL):
Volume · รายรับ · ส่วนลด · จำนวนบิล **ตรงกันหมดทุกตัว** และ ThaiHand total = 967,419฿
เท่ากับค่าจริง (เดิมจะโชว์ 883,788฿)

เครดิตแถมที่ถอดจากสมการต่างจากผลบวก `bonus_used` รายแถว 0.000003฿ — เศษทศนิยม
จากการปัดตอนบันทึกรายบิล มองไม่เห็นบนจอ และเป็นพฤติกรรมเดียวกับหน้า `/today` อยู่แล้ว
