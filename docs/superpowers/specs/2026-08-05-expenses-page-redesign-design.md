**วันที่:** 5 ส.ค. 2569
**สถานะ:** เจ้าของร้านอนุมัติ design แล้ว

## เป้าหมาย

ทำให้หน้า `/expenses` ดูรายการรายจ่ายได้สบายตาขึ้น และเปลี่ยนเดือนได้ง่ายขึ้น
โดยย้ายสรุปหมวดหมู่ไปเป็นกราฟวงกลมด้านข้าง และเปลี่ยนปุ่มลูกศร ← → เป็นชิพเลือกเดือน

## ปัญหาของหน้าปัจจุบัน

| ปัญหา | รายละเอียด |

### มือถือ (< lg)

เรียงลงมาทีละบล็อก: แถบเลือกช่วง → การ์ดยอดรวม (วงกลมย่อ 46px วางซ้าย ยอดรวมขวา) → รายการเต็มความกว้าง

วงกลมบนมือถือไม่มี legend เพราะกินที่ — แตะวงกลมแล้วเลื่อนลงไปที่รายการหมวด
(ใช้ `<details>` กางรายการหมวดออกมาแทน ไม่ต้องเขียน JS)

## แถบเลือกช่วง

สองแถวแยกกันชัด ไม่ปนกัน เพื่อให้รู้เสมอว่ากำลังดูอะไร

**แถวบน — ดูทีละเดือน:** ชิพ 6 เดือนล่าสุดนับจากเดือนปัจจุบัน (ใหม่สุดอยู่ซ้าย)
ชิพที่กำลังดูอยู่เป็นสีเน้น · ท้ายแถวมีปุ่ม "เลือกเดือนอื่น" เปิด `<input type="month">`
สำหรับย้อนไกลกว่า 6 เดือน (แบบเดียวกับ DateJump ในหน้าค่ามือ)

**แถวล่าง — ดูรวมช่วง:** ชิพ "3 เดือน" และ "6 เดือน" = รวมยอดของ N เดือนล่าสุดจนถึงเดือนปัจจุบัน

### สัญญา URL

| พารามิเตอร์ | ความหมาย |
|---|---|
| `?month=YYYY-MM` | ดูเดือนเดียว (ของเดิม) ค่าเริ่มต้น = เดือนปัจจุบัน |
| `?months=3` หรือ `?months=6` | ดูรวมช่วง N เดือนล่าสุด — **มีตัวนี้เมื่อไหร่ให้ชนะ `month` เสมอ** |
| `?category=<ชื่อหมวด>` | กรองเฉพาะหมวดนั้น (ของเดิม ใช้ได้ทั้งสองโหมด) |

ค่า `months` ที่ไม่ใช่ 3 หรือ 6 ให้ถือว่าไม่ได้ส่งมา (ตกกลับไปโหมดเดือนเดียว)

## กราฟวงกลม

### สูตร — `donutSlices()` ใน `src/lib/chart.ts`

ฟังก์ชันบริสุทธิ์ เทสได้ ไม่แตะ DOM:

```ts
export type DonutSlice = {
  label: string
  value: number
  /** สัดส่วนเป็น % ของยอดรวม */
  pct: number
  /** % สะสมก่อนหน้าชิ้นนี้ ใช้หมุน stroke ให้ต่อกัน */
  startPct: number
}

export const DONUT_MIN_PCT = 5

export function donutSlices(points: Point[], minPct?: number): DonutSlice[]
```

กติกา:
- ตัดค่า 0 และติดลบทิ้ง (รายจ่ายติดลบไม่มีความหมายบนวงกลม)
- เรียงจากมากไปน้อย
- ชิ้นที่เล็กกว่า `minPct` ยุบรวมเป็น "อื่นๆ" ต่อท้ายเสมอ **ยกเว้น**ถ้ายุบแล้วเหลือชิ้นเดียว ให้ไม่ยุบ
  (วงกลมที่มีชิ้นเดียวชื่อ "อื่นๆ" ไม่ได้บอกอะไรเลย)
- ถ้ามีหมวดชื่อ "อื่นๆ" อยู่แล้ว ให้รวมเข้าก้อนเดียวกัน ไม่สร้างสองชิ้นชื่อซ้ำ
- ยอดรวมเป็น 0 หรือไม่มีข้อมูล → คืน `[]`
- `startPct` ของชิ้นแรกเป็น 0 และแต่ละชิ้นบวกสะสมไปเรื่อยๆ

### Component — `src/components/charts/donut-chart.tsx`

server component ส่งฟังก์ชันข้ามไป client ไม่ได้ ดังนั้น**ห้ามรับ callback หรือ `hrefOf`**
ให้ฝั่ง server คำนวณ `href` กับ `color` ใส่มาในข้อมูลให้พร้อมใช้:

```ts
export type DonutSliceLink = DonutSlice & { href: string; color: string }

export function DonutChart({
  slices,
  size = 120,
  /** ชื่อหมวดที่กำลังกรองอยู่ — ชิ้นนี้จะหนากว่าเพื่อน */
  activeLabel = null,
}: {
  slices: DonutSliceLink[]
  size?: number
  activeLabel?: string | null
})
```

วาดด้วย `<circle>` ซ้อนกัน ใช้ `stroke-dasharray` + `transform="rotate()"` ตามสัดส่วน
(ไม่ใช้ arc path เพราะคณิตซับซ้อนกว่าโดยไม่ได้อะไรเพิ่ม) แต่ละชิ้นห่อด้วย `<a>` กดได้
ชิ้นที่กำลังถูกกรองอยู่ให้หนาขึ้น (stroke-width มากกว่าชิ้นอื่น) เป็นการบอกสถานะ

**สี** — ชุดคงที่ 8 สีวนซ้ำ เรียงตามลำดับชิ้น (ไม่ผูกกับชื่อหมวด เพราะหมวดแก้ชื่อได้จากหน้าตั้งค่า):
`#7F77DD #1D9E75 #D85A30 #378ADD #BA7517 #D4537E #639922 #888780`
ชิ้น "อื่นๆ" ใช้เทา `#888780` เสมอ

## โหมดรวมช่วง

- ช่วงวันที่ = ตั้งแต่วันที่ 1 ของเดือน `shiftMonth(เดือนปัจจุบัน, -(N-1))` ถึงวันสุดท้ายของเดือนปัจจุบัน
- รายการคั่นด้วยหัวข้อเดือนพร้อมยอดรวมของเดือนนั้น เรียงเดือนใหม่สุดขึ้นก่อน
  ภายในแต่ละเดือนเรียงตามวันที่ใหม่ไปเก่า
- การ์ดยอดรวมและกราฟวงกลมคิดจากทั้งช่วง
- หัวการ์ดเขียนช่วงให้ชัด เช่น "รายจ่าย มี.ค. – ส.ค. 69"

### เพดานจำนวนแถว

`limit(300)` เดิมไม่พอสำหรับ 6 เดือน (มี.ค.–ส.ค. รวม ~200 แถว ยังพอ แต่จะเกินภายในสิ้นปี)
ขยายเป็น `limit(1000)` และ**ถ้าดึงได้ครบ 1000 แถวพอดี ให้ขึ้นข้อความเตือนใต้รายการ**
ว่าแสดงไม่ครบ — ห้ามตัดเงียบ ไม่งั้นยอดรวมกับรายการจะไม่ตรงกันโดยไม่มีใครรู้

> ยอดรวมและกราฟวงกลมคิดจากแถวที่ดึงมาได้เท่านั้น การเตือนจึงจำเป็น

## ฟอร์มบันทึกรายจ่าย

เลิกใช้ `<Tabs>` — เปลี่ยนเป็นปุ่ม "+ บันทึกรายจ่าย" มุมขวาบนของแถบเลือกช่วง
กดแล้วเปิด `<Dialog>` ที่ห่อ `ExpenseForm` เดิมไว้ (ไม่แก้ตัวฟอร์ม)

- บันทึกสำเร็จ → ปิด dialog เอง (ฟอร์มเรียก `router.refresh()` อยู่แล้ว รายการจะอัปเดตตาม)
- กล่องเตือนรายการซ้ำที่มีอยู่ยังทำงานเหมือนเดิมภายใน dialog
- **ผลข้างเคียงที่ต้องรู้:** ลิงก์ที่เคยพาไปแท็บ "รายการ" ไม่ต้องมี `defaultValue` อีกแล้ว
  เพราะไม่มีแท็บ — ทุกลิงก์เข้าหน้านี้เห็นรายการทันที (ดีขึ้นกว่าเดิม)

## กรณีพิเศษ

| กรณี | พฤติกรรม |
|---|---|
| เดือนที่ไม่มีรายจ่ายเลย | ไม่วาดวงกลม ขึ้นข้อความ "ยังไม่มีรายจ่ายในเดือนนี้" · การ์ดยอดรวมโชว์ 0 |
| กรองหมวดแล้วไม่เหลือแถว | ข้อความ "ไม่มีรายจ่ายหมวด X ในช่วงนี้" + ลิงก์ "ดูทุกหมวด" (ของเดิม) |

## การทดสอบ

**เขียนเทสก่อนโค้ด (TDD) เฉพาะสองฟังก์ชันสูตร:**

`donutSlices`
- เรียงมากไปน้อย · `pct` รวมกันได้ 100
- `startPct` สะสมถูกต้อง ชิ้นแรกเป็น 0
- ชิ้นต่ำกว่า 5% ยุบเป็น "อื่นๆ" ชิ้นเดียวต่อท้าย
- หมวดชื่อ "อื่นๆ" ที่มีอยู่แล้วรวมเข้าก้อนเดียวกัน ไม่ซ้ำ
- ยุบแล้วจะเหลือชิ้นเดียว → ไม่ยุบ
- ค่า 0 และติดลบถูกตัดทิ้ง
- ไม่มีข้อมูล / รวมเป็น 0 → คืน `[]`
- **ตัวเลขจริงเดือน มิ.ย. 69 (หลังสางบัญชีกับ Paypers แล้ว รวม 325,845.68):**
  ค่ามือหมอ 141,735 · เงินเดือนประจำ 52,450 · ค่าเช่า 36,000 · อื่นๆ 30,320 ·
  การตลาด 20,400 · วัสดุ-สิ้นเปลือง 18,843.15 · ค่าน้ำค่าไฟ 16,197.53 · ซักรีด 9,900

  ผลที่ต้องได้ 7 ชิ้น — ค่ามือ 43.5% · เงินเดือน 16.1% · ค่าเช่า 11.0% · การตลาด 6.3% ·
  วัสดุ 5.8% และ **"อื่นๆ" = 56,417.53 (17.3%)** ซึ่งเป็นหมวด "อื่นๆ" เดิม 30,320
  บวกกับค่าน้ำค่าไฟ (4.97%) และซักรีด (3.04%) ที่ต่ำกว่าเกณฑ์ ยุบเข้าก้อนเดียวกัน
  → เคสนี้พิสูจน์กติกา "หมวดชื่ออื่นๆ ที่มีอยู่แล้วต้องรวมเข้าก้อนเดียว ไม่แตกเป็นสองชิ้น"

  หมายเหตุ: ค่าน้ำค่าไฟอยู่ที่ 4.97% เฉียดเกณฑ์ 5% มาก — เป็นเคสขอบที่ดี
  ถ้าสูตรปัดเศษผิดทางจะหลุดออกจากก้อน "อื่นๆ" แล้วเทสจะจับได้ทันที

`recentMonths`
- `recentMonths("2026-08-05", 6)` → `["2026-08","2026-07","2026-06","2026-05","2026-04","2026-03"]`
- ข้ามปีถูกต้อง: `recentMonths("2026-01-15", 3)` → `["2026-01","2025-12","2025-11"]`
- `count` เป็น 1 → คืนเดือนเดียว

**ตรวจด้วยตาบนเบราว์เซอร์ก่อนปิดงาน** — จอคอมและมือถือ (resize 375px):
กดชิพเดือนแล้วเปลี่ยนจริง · กดชิ้นวงกลมแล้วกรอง · กด 3/6 เดือนแล้วเห็นหัวข้อเดือนคั่น ·
เปิด dialog บันทึกแล้วปิดได้ · ยอดรวมในการ์ดตรงกับผลรวมของรายการที่แสดง

## สิ่งที่ไม่ทำ (YAGNI)
